# 단원 사용 준비 스펙

가입·메일 항목은 당시 설계의 기록입니다. 현재 운영 기준은 [운영진 계정 발급 스펙](operator-accounts-spec.md)을 따릅니다.

작성일: 2026-09-28

## 목적과 범위

기존 회원 포털을 일반 단원이 휴대전화에서 가입 신청부터 출석 기록 확인까지 사용할 수 있는 수준으로 정리한다. 이 작업은 기존 가입·승인·공지·행사·출석 API를 새로 설계하지 않고, 화면의 누락된 상태와 검증의 빈틈을 보완한다. 공개 온보딩과 로그인 시안의 별도 디자인 변경, 실제 배포와 운영 정보 입력은 범위 밖이다.

## 현재 확인된 상태

- 승인·행사·공지·출석의 서버 기능과 단위·통합 테스트가 있다.
- 회원 일정 화면, 공지, 내 출석 화면은 최근 디자인 변경을 거쳤다.
- 운영진의 가입 신청·공지·출석 관리 화면과 가입 신청·상태 화면은 공통 화면 체계가 부족하다. 행사 관리에는 이전 색상과 카드 스타일이 남아 있다.
- 디자인 변경 뒤 전체 브라우저 통합 테스트가 재실행되지 않았다. 현재 별도 로컬 미리보기가 통합 테스트의 고정 포트를 사용한다.

## 사용자 흐름과 화면

1. 신청자는 이름, 이메일, 비밀번호로 가입 신청하고 이메일 확인 및 운영진 승인 상태를 구분해서 확인한다.
2. 운영진은 신청자의 이름·이메일·신청일을 명단과 대조한 뒤 활동 단원 또는 OB로 승인하거나 이유를 입력해 반려한다. 화면은 명단 대조를 자동으로 수행했다고 주장하지 않는다.
3. 승인된 단원은 일정에서 행사를 찾고, 상세·공지·본인 출석 상태로 이동한다. 모바일에서도 탐색과 입력에 가로 스크롤이 없어야 한다.
4. 운영진은 공지·행사를 작성하고 출석 창을 열어 QR 또는 코드를 보여주며, 단원 기록을 확인하고 이유를 남겨 정정한다. 화면은 요청 중 중복 제출을 막고, 성공·실패·새로고침 실패를 구분한다.
5. 단원은 유효한 출석 코드 또는 QR로 출석하고 성공, 중복, 만료, 대상 아님, 승인 대기 상태를 구분해 확인한다.

## 화면 규칙

- 회원·운영진 내부 화면은 흰 바탕, 합창단 초록색, 얇은 구분선과 공통 내비게이션을 사용한다.
- 운영진 화면에는 신청·공지·행사로 이동하는 공통 경로가 있다. 제목, 목록, 편집 영역의 순서를 화면마다 일정하게 유지한다.
- 장식용 보조 문구나 확인되지 않은 활동 소개 문구를 추가하지 않는다. 필요한 절차 안내와 오류 문구만 쓴다.
- 로딩, 빈 목록, 저장 완료, 오류, 권한 없음 상태를 구분한다. 입력 필드는 레이블과 키보드 초점을 제공한다.

## 권한과 자료 경계

기존 서버 권한 검사를 유지한다. 미승인·접근 해제 계정은 회원 자료를 볼 수 없고, 일반 단원은 운영진 변경 API를 사용할 수 없다. 공개 경로는 비공개 행사, 회원 공지, 개인 출석을 반환하지 않는다. 출석과 승인 결과는 서버 응답이 확인된 뒤에만 완료로 표시한다.

## 완료 기준

- 가입 신청 → 이메일 확인 → 승인 → 로그인 → 일정 확인 → 코드·QR 출석 → 본인 기록 → 운영진 정정의 브라우저 흐름이 격리 환경에서 통과한다.
- 활동 단원, OB, 미승인 신청자, 접근 해제 계정, 운영진의 권한 경계가 API 테스트에서 통과한다.
- 운영진 화면과 주요 단원 화면을 390px 및 데스크톱 폭에서 확인하고 가로 넘침, 주요 동작의 가림, 브라우저 오류가 없다.
- 웹 단위 테스트·린트·빌드와 API 전체 테스트가 통과한다.
- 실제 메일·도메인·HTTPS·첫 운영진·명단 대조 절차가 준비되기 전에는 운영 배포 완료로 판정하지 않는다.
