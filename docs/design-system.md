# 합창단 디자인 시스템

작성일: 2026-09-30. 이 문서는 공개·인증·회원·운영진 화면의 시각 규칙에 적용합니다. 인증과 권한은 구글 로그인 스펙, 일정과 출석은 운영 절차를 따릅니다.

## 기준과 확인 범위

- 팔레트는 사용자가 승인한 기존 로고 초록색을 유지합니다. 브랜드 `#008a3e`, 주요 동작 `#006b34`, 본문 `#202823`, 구분선 `#dfe8e0`입니다.
- 내부 UI 참고는 [EEOS 공식 소스](https://github.com/JNU-econovation/EEOS)입니다. 버튼의 크기·역할 분리와 6~8px 모서리, 흰 배경, 고정 헤더, 제목·목록·편집 영역 구성을 참고합니다. EEOS의 노란색은 합창단 초록색으로 대체합니다.
- 공개·로그인 참고는 [Record Club](https://record.club/)입니다. 공개 페이지의 섹션 구성은 확인했으나 직접 화면 확인은 접근 제한으로 완료하지 못했습니다. 현재 적용은 기존 승인된 레이아웃의 공통 규칙 정리이며, Record Club의 시각적 재현을 완료했다고 판단하지 않습니다. 실제 화면과 비교한 뒤 공개 페이지 배치·에셋을 확정합니다.
- 임의의 일러스트·캐릭터·소개 문구를 만들지 않습니다. 기존 로고와 승인된 사진을 사용하며 장식용 보조 문구는 추가하지 않습니다. 절차 안내, 실제 일정, 투표 마감, 오류 문구는 유지합니다.

## 토큰

`web/src/styles/tokens.css`가 색상·글자·간격·모서리·콘텐츠 폭·모션의 단일 정의입니다. 기능 CSS에 새로운 색상값을 직접 추가하지 않습니다. 기존 `--choir-*` 변수는 이 토큰을 참조합니다.

| 항목 | 규칙 |
| --- | --- |
| 폰트 | Pretendard 가변 폰트 1.3.9를 로컬 제공. 굵기 45~920, 대체 글꼴과 `swap` 사용 |
| 글자 | 본문 16px, 라벨 14px, 작은 정보 13px, 섹션 21px, 페이지 제목 30~42px |
| 글자 굵기 | 본문 400, 중간 550, 라벨 650, 제목 750 |
| 간격 | 4px 단위를 기본으로 8·12·16·20·24·32·40·48·64·80px 사용 |
| 콘텐츠 | 공개 최대 1320px, 내부 최대 1240px, 상세 최대 880px |
| 모바일 | 좌우 20px. 입력 글자는 16px 이상. 목록과 폼은 세로로 전환 |
| 컨트롤 | 작은 버튼 36px, 일반 44px, 주요 진입 52px. 모바일 직접 선택은 44px 이상 |
| 모션 | 상태 전환 160ms, 공개 섹션 등장 540ms. 모션 줄이기 설정에서는 이동과 전환 제거 |

공개 제목에는 별도 큰 글자 토큰을 사용합니다. 내부 화면의 날짜·상태·응답은 정보 밀도를 유지합니다.

히어로의 악보는 로고와 제목 사이를 화면 전체 폭으로 지나가며 26초 주기로 흐릅니다. SVG 반복 무늬와 한 칸의 여분으로 넓은 화면에서도 이미지 끝이 드러나지 않게 합니다. 악보 위아래에는 데스크톱 약 64px, 모바일 약 40px 이상의 시각적 여백을 둡니다. 강조 문구 ‘울림과 감동’은 글꼴 로드 후 글자별 85ms 간격으로 작은 파동을 한 번 실행하고 약 1.8초 안에 멈춥니다. 모션 줄이기 설정에서는 악보와 글자 모션을 모두 제거하며, 문구는 자바스크립트 실행 전에도 표시합니다.

## 승인된 공개 메인 구성

2026-10-01 사용자가 검토한 메인 시안의 배치를 적용합니다. 메인의 콘텐츠 폭은 시안과 같은 1280px이며, 내부 화면의 기존 폭과 팔레트는 유지합니다.

- 히어로(제목과 중앙동아리 소개) → 악보 길을 따라 읽는 네 문장 → 정적 소식과 사진 → 지원 문의 → 접힌 연혁 → 공식 채널 순서입니다. 2026-10-02에 스크롤로 닿는 영역으로 이동하는 히어로 버튼을 없애고, 별도 초록 소개 영역의 문장을 히어로로 옮겼습니다.
- 히어로는 화면 높이에 고정하지 않습니다. 버튼 대신 다음 영역의 일부가 첫 화면 아래에 보여 스크롤을 유도합니다. 390×844에서는 첫 문장, 1440×900에서는 악보 곡선의 시작이 보입니다.
- `ScoreJourney`가 스크롤 진행률과 화면 크기에 맞춰 오선과 음표를 배치합니다. 화면 밖에서는 스크롤 계산을 멈추며, 모션 줄이기 설정에서는 완성된 악보를 표시합니다. 마지막 문장의 배경은 투명하고 오선은 글자 옆을 지나 아래로 이어집니다.
- 공개 소식은 `newsItems.ts`, 사진은 `activityPhotos.ts`, 연혁과 채널은 `choirProfile.ts`에서 관리합니다. 항목 추가를 위해 렌더링 코드를 복제하지 않습니다. 정적 자료 변경은 커밋과 재배포가 필요합니다.
- 회원 공지·행사 DB와 공개 소식은 분리합니다. 제공된 사진에 확인되지 않은 촬영 날짜나 특정 공연명을 붙이지 않습니다.
- ‘지원서 작성하기’는 `choirProfile.ts`의 구글 폼 지원서로 연결합니다. 단원 로그인은 헤더에만 두며 기존 `/login`으로 이동합니다. 처음 방문한 지원자용 영역에는 단원 로그인을 두지 않습니다.
- 연혁은 기본적으로 접고 기본 HTML 펼침 동작을 사용합니다. 자바스크립트가 없어도 소개·소식·링크·연혁을 읽을 수 있습니다.
- 스크롤 경로 구현은 [Codrops의 반응형 곡선 모션 사례](https://tympanus.net/codrops/2025/12/17/building-responsive-scroll-triggered-curved-path-animations-with-gsap/)와 [SVG 경로 좌표 API](https://developer.mozilla.org/en-US/docs/Web/API/SVGGeometryElement/getPointAtLength)를 참고합니다. 모션 라이브러리를 새로 추가하지 않습니다.

## 공통 컴포넌트

`web/src/components/ui/index.tsx`와 `ui.module.css`에 정의합니다.

- `Button`: 주요·일반·위험·텍스트·달력/목록용 스타일, 크기, 비활성·선택·초점 상태. 기본 타입은 `button`, 제출은 명시적으로 `submit`입니다.
- `ActionLink`: 이동용 링크에 같은 버튼 스타일을 적용합니다. API 작업에는 사용하지 않습니다.
- `Input`, `Select`, `Textarea`: 기존 표준 속성과 이벤트를 그대로 전달합니다. 입력 라벨은 각 화면에서 실제 입력과 연결합니다. 체크박스·라디오의 기본 의미는 유지합니다.
- `PageHeader`: 제목과 선택적인 작업 영역을 같은 순서·간격으로 구성합니다.
- `StatusBadge`: 긍정·중립·오류 상태를 글자와 색으로 함께 표시합니다.
  - 공지 투표 미리보기는 제목 아래에 배치합니다. 미참여는 중립 회색, 응답한 투표는 본인 선택만 긍정 초록색으로 표시합니다. 마감한 투표는 중립 회색으로 마감 상태와 본인 선택을 함께 표시합니다. 일반 공지에는 배지가 없습니다. 긴 선택지는 모바일에서 줄바꿈하며, 제목 버튼의 접근 가능한 설명에도 상태를 연결합니다.
- `Feedback`: 성공은 `status`, 오류는 `alert`로 알립니다. 표시 시점은 서버 응답을 기준으로 합니다.
- `BrandLogo`: 가로 로고와 심벌을 재사용하며 이미지 비율과 대체 텍스트를 유지합니다.

달력, 투표, 참석 응답, 갤러리는 기능 컴포넌트를 유지하면서 공통 요소와 토큰을 사용합니다. 데이터 추가를 위해 레이아웃 코드를 복제하지 않습니다.

- 2026-10-01 공개 메인 적용 검증: 프로덕션 빌드, 린트, 기존 웹 테스트 53개 통과. 브라우저에서 320·390·768·1440·2839px 가로 넘침, 악보 반복, 스크롤 진행, 소식 사진 로드, 섹션 이동, 연혁 펼침을 확인했습니다. 모션 줄이기 설정과 자바스크립트 비활성 상태도 확인했습니다.
- 개발 환경의 `/design-system`에서 팔레트, 제목, 버튼·선택·입력·피드백 상태를 한 화면에서 확인합니다. 운영 환경에서는 이 경로가 404를 반환합니다.
- 대표 화면은 공개 메인, 로그인, 회원 일정, 공지·투표, 운영진 행사·회원 관리입니다. 데스크톱 1440px와 모바일 390px에서 확인합니다.
- 키보드 초점, 로고·글꼴 로드, 모바일 가로 넘침, 긴 제목·이메일, 선택·비활성 상태와 기존 저장 동작을 확인합니다.
- 디자인 기반과 화면 적용을 별도 커밋으로 남깁니다. 배포 여부는 구현·빌드 결과와 별도로 기록합니다.

## 적용 검증 기록

### 파비콘 (2026-10-01)

- 기존 합창단 심벌을 원본 비율로 사용해 브라우저 탭용 48×48 PNG와 애플 홈 화면용 180×180 PNG를 빌드 시 생성합니다. 두 크기는 `brandIcon` 렌더러를 공유하고 흰 배경을 사용합니다.
- 린트와 운영 빌드가 통과했습니다. 로컬 운영 빌드의 메인·로그인 페이지에서 아이콘 연결 태그, PNG 형식·크기와 200 응답을 확인하고 실제 생성 이미지를 시각 확인했습니다. 운영 반영은 재배포 후 확인합니다.

### 링크 공유 미리보기 (2026-10-01)

- 루트의 `opengraph-image.tsx`에서 기존 가로 로고를 흰 배경 중앙에 배치한 1200×630 PNG를 빌드 시 생성합니다. 기존 로고 비율을 유지하며 단체사진이나 추가 문구를 사용하지 않습니다.
- 공유 이미지의 절대 주소 기준은 현재 운영 주소 `https://cnuc-hoir-page.vercel.app`입니다. 운영 도메인을 변경하면 `layout.tsx`의 `metadataBase`도 변경합니다.
- 린트와 운영 빌드가 통과했습니다. 로컬 운영 빌드에서 카카오톡·페이스북 수집기 식별자로 요청해 Open Graph와 트위터 이미지 주소, 대체 텍스트, 이미지의 200 응답·PNG 형식·1200×630 크기를 확인했습니다. 생성된 이미지는 약 38KB이며 직접 시각 확인했습니다.
- 실제 메신저의 미리보기 표시와 캐시 갱신은 배포 후 확인합니다.

### 공지 목록 투표 상태 (2026-10-01)

- 기존 `StatusBadge`의 중립·긍정 토큰을 재사용합니다. 미참여는 회색, 응답한 투표는 본인 선택만 초록색, 마감은 본인 선택과 함께 회색으로 표시하며 일반 공지에는 배지를 붙이지 않습니다.
- 저장 성공 이후에만 미리보기를 갱신합니다. 선택 변경, 저장 실패, 상세 조회에서 확인한 마감 상태, 화면을 열어 둔 동안의 마감 전환을 웹 테스트로 확인했습니다.
- 웹 테스트 21개 파일 66개, 린트와 운영 빌드가 통과했습니다. Docker의 PostgreSQL 17로 공지·투표 통합 테스트 10개가 통과했습니다. 본인 선택 분리, 초안 제외, 승인 권한, 페이지 이동과 빈 페이지를 확인했습니다.
- 운영 빌드를 320·390·1440px에서 확인했습니다. 긴 선택지의 줄바꿈과 회색·초록색 배경, 저장·변경·닫기·새로고침 후 상태 유지를 확인했습니다. 목록을 읽기 위해 공지마다 투표 API를 호출하지 않습니다.
- 브라우저 검증은 모의 API 응답을 사용했고 DB 검증은 격리된 테스트 컨테이너를 사용했습니다. 운영 배포와 실제 구글 로그인 재검증은 포함하지 않습니다.

### 일반 단원 화면 개선 (2026-10-01)

- 적용 범위는 일정, 행사 상세, 공지와 투표, 내 출석, 현장 출석입니다. 기존 EEOS 기반 내부 규칙과 로고 팔레트를 사용합니다.
- 달력은 요일 머리글이 있는 HTML 표로 구성하고 날짜 버튼에 전체 날짜, 선택 여부와 오늘 표시를 제공합니다. 월간 행사 목록은 목록 마크업과 선택 강조를 사용하며 참석 선택 버튼은 최소 44px 높이를 유지합니다.
- 공지는 제목 아래에서 본문과 투표를 펼칩니다. [W3C 펼침 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/)에 따라 제목 버튼의 펼침 상태와 본문 연결을 제공하고, 닫으면 제목으로 초점을 돌립니다. 대시보드 공지 링크는 `?notice=번호`로 해당 공지를 직접 엽니다. 첫 페이지 밖의 공지도 기존 상세 API로 조회합니다.
- 날짜는 `time`, 출석 결과는 공통 상태 배지로 표시합니다. 참석 응답과 투표의 저장 완료는 보조 낭독 안내로 전달합니다. 장식용 보조 문구는 추가하지 않습니다.
- 회원 화면은 본문 영역과 페이지 제목을 각각 하나씩 제공하고 본문 건너뛰기 링크를 사용합니다. 출석 코드 오류는 입력의 오류 상태와 설명을 연결합니다.
- 일정과 출석 조회 중에는 빈 목록으로 안내하지 않습니다. 조회 실패에는 다시 시도 동작을 제공하고, 빠르게 공지를 바꿔 열었을 때 오래된 본문 응답이 현재 선택을 덮지 않습니다.
- 린트, 운영 빌드, 웹 테스트 20개 파일 61개가 통과했습니다. 다섯 화면을 320·390·1440px에서 확인했으며 가로 넘침이나 브라우저 실행 오류가 없었습니다. 운영 빌드의 모바일 브라우저에서 본문 건너뛰기, 참석 응답, 공지 직접 열기와 투표 저장, 출석 오류 수정 후 저장을 확인했습니다.
