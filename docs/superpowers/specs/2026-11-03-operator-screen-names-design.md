# 운영진 화면 명칭 설계

작성일: 2026-11-03. 대상: 운영진 하위 메뉴, `/admin/members`와 `/admin/applications`의 제목과 절 제목, 버튼, 안내와 오류 문구, 브라우저 탭 제목, `docs/operations.md`, `docs/design-system.md`, 새 `docs/glossary.md`. 경로와 API, 서버 코드는 바꾸지 않는다.

## 왜 바꾸는가

운영진 화면의 이름이 어느 서비스에나 붙을 수 있는 말이다. "단원 계정", "계정 목록", "미리 승인", "접근 해제"는 그 자리에서 무슨 일을 하는지 합창단 말로 말해 주지 않는다. 2026-10-22 점검에서 단원 화면의 "행사"를 "일정"으로, "회원"을 "단원"으로 맞췄듯 운영진 화면도 같은 기준으로 맞춘다. 기준은 `docs/design-system.md`의 용어 정리와 `docs/operations.md`가 쓰는 말이다. 사용자는 2026-11-03 운영진이 실제 쓰는 말을 묻는 대신 제안을 받아 그대로 확정했다.

## 결정한 것

### 바꾸는 이름

| 지금 | 바꾼 뒤 | 쓰이는 곳 |
| --- | --- | --- |
| 단원 계정 | 단원 정보 관리 | 하위 메뉴, `/admin/members` 제목, 탭 제목, 다른 화면이 이 화면을 가리키는 문구 |
| 미리 승인 | 사전 등록 | `/admin/members` 첫 절 제목. 버튼은 "사전 등록" |
| 미리 승인한 이메일 | 사전 등록된 단원 | 같은 절의 오른쪽 목록 제목 |
| 계정 목록 | 단원 명단 | `/admin/members` 둘째 절 제목, 대기 문구, 빈 목록 문구 |
| 정보 수정 | 단원 정보 수정 | 단원 상세의 펼침 제목과 화면 읽기 이름 |
| 접근 해제 | 포털 이용 중단 | 단원 상세의 펼침 제목, 이유 입력 이름, 빨간 버튼. 상태 배지와 목록 줄의 상태 글자는 "이용 중단" |

- 하위 메뉴 순서는 그대로다. 단원 정보 관리, 가입 승인, 공지 관리, 일정 관리.
- 문장 안의 말도 같이 바꾼다. "단원 계정을 불러오지 못했습니다"는 "단원 명단을 불러오지 못했습니다", "등록된 계정이 없습니다"는 "등록된 단원이 없습니다", "계정 목록을 불러오는 중입니다"는 "단원 명단을 불러오는 중입니다"다. 가입 승인 화면의 반려 확인 문구가 말하는 "단원 계정 화면"은 "단원 정보 관리 화면"이다.
- "사전 등록"은 사용자가 2026-11-03 고른 말이다. `docs/operations.md`가 운영진 사전 등록 목록이라고 부르던 것과도 이어진다. 처음 보는 운영진에게는 뜻이 바로 안 잡힐 수 있으므로, 절 제목 바로 아래의 지금 설명 칸(`.callout`)을 노션의 콜아웃처럼 제목이 있는 안내 상자로 바꾼다. 첫 줄은 굵게 "사전 등록이 뭔가요?", 그 아래 두세 문장이다. 명단에 있는 새 단원의 Gmail을 미리 등록해 두는 일이다. 등록된 사람은 구글 계정으로 처음 로그인할 때 승인 없이 바로 단원이 된다. 등록하지 않은 사람이 로그인하면 가입 승인에 올라오고, Gmail이 아닌 주소는 아래 1회용 링크로 초대한다. 마크업은 `aside`로 두고 새 스타일은 만들지 않는다.
- 사전 등록된 단원 목록의 안내는 "아직 로그인하지 않은 사람입니다. 로그인하면 이 목록에서 사라지고 단원 명단에 나타납니다. 여기서 삭제해도 이미 승인된 단원은 그대로입니다."로 맞춘다.
- 가입 승인 알림 띠의 "가입 승인을 기다리는 단원"과 이 목록은 서로 다른 사람이다. 띠는 등록 없이 로그인해 승인을 기다리는 신청자, 이 목록은 등록만 되고 아직 로그인하지 않은 사람이다. 두 이름에 같은 말이 들어가지 않게 한 것이 이 결정의 이유다.
- "포털 이용 중단"은 사용자가 가장 확신이 낮다고 들은 항목이지만 그대로 가기로 했다. 영구 조치로 들리지 않을 수 있으니 펼침 안의 안내 한 줄에 "이용을 중단한 단원은 다시 초대해야 포털을 쓸 수 있습니다"를 적는다. 상태 "이용 중단"인 단원에게 지금 보이는 "다시 초대" 버튼은 그대로다.

### 그대로 두는 이름

가입 승인, 공지 관리, 일정 관리, 운영진(상단 메뉴), 단원 구분, 활동 단원, OB, 사이트 관리자, 승인, 반려, 반려 취소, 가입 신청 반려, 1회용 링크로 초대, 초대 대기, 이메일 확인 대기, 승인 대기, 사용 중, 가입 반려, 직책 추가, 사이트 관리자 지정과 해제, 계정 연결 링크 발급. 이미 합창단 말이거나 누르면 무슨 일이 생기는지 분명하다.

### 코드에서 바꾸지 않는 것

- 경로 `/admin/members`, `/admin/applications`.
- API 경로, 권한 이름(`REVOKE_ACCESS`, `MANAGE_ALLOWLIST` 등), 서버의 enum과 클래스 이름(`OperatorPreapproval`, `MemberAllowlist`).
- 서버가 돌려주는 오류 문구. 다만 화면에 그대로 보이는 문구 중 "접근 해제"가 든 것("마지막 운영진의 접근은 해제할 수 없습니다")은 "포털 이용 중단"으로 글자만 고쳐도 된다. 빌더 선택이다. 고치면 서버 테스트의 기대 문구도 함께 고친다.

### 문서

- 새 `docs/glossary.md`: 이 사이트의 용어 사전. 표 하나로 "화면 이름, 뜻, 쓰이는 화면, 코드 이름"을 적는다. 단원, 활동 단원, OB, 기수, 파트, 직책, 운영진, 사이트 관리자, 가입 신청, 승인 대기, 승인, 반려, 사전 등록(자동 승인 명단, `MemberAllowlist`), 사이트 관리자 권한도 부여(운영진 사전 등록, `OperatorPreapproval`), 사전 등록된 단원, 1회용 링크 초대, 단원 명단, 단원 정보, 포털 이용 중단(`REVOKE_ACCESS`), 일정과 네 종류(정기연습, 비정기연습, 파트연습, 중요 행사), 참석 응답, 출석과 지각과 미출석, 정정, 공지, 초안, 게시, 투표. 피해야 할 말도 한 줄로 적는다. 회원, 행사(일정 전체를 가리킬 때), 계정 목록, 미리 승인, 접근 해제.
- `docs/operations.md`: "자동 승인 명단에 추가하거나, 운영진으로 지정할 이메일을 운영진 사전 등록 목록에 추가"를 "단원 정보 관리에서 사전 등록하고, 사이트 관리자로 둘 사람은 '사이트 관리자 권한도 부여'를 켠다"처럼 화면 이름으로 고친다. "접근 해제"는 "포털 이용 중단(접근 해제)"로 처음 한 번 병기하고 그 뒤는 "포털 이용 중단"으로 쓴다. 기술 용어가 처음 나오는 곳에만 괄호로 남긴다.
- `docs/design-system.md`: 2026-10-22 용어 줄 아래에 이번 변경을 한 줄로 더하고, 공통 규칙으로 "운영진 화면 이름은 `docs/glossary.md`를 따른다"를 적는다.

## 하지 않는 것

- 화면 구조나 동작 변경. 이 PR은 글자만 바꾼다.
- 경로 변경이나 리다이렉트.
- 서버 API나 DB 변경.

### 바꾸는 범위

- 바꾼다: `web/src` 전체(화면, 테스트, 개발용 `/design-system` 미리보기, CSS 주석), `web/e2e`의 문구(지금은 CI에 걸려 있지 않고 옛 로그인 흐름이지만 문구는 맞춘다), `docs/operations.md`, `docs/design-system.md`, 새 `docs/glossary.md`.
- 건드리지 않는다: 서버 코드와 주석과 메시지(위의 선택 항목 하나만 예외), 옛 설계와 계획 문서(`docs/*-spec.md`, `docs/*-plan.md`, `docs/superpowers/` 아래 지난 날짜 문서). 그 문서들은 쓴 날의 기록이다.

## 빌더에게 남긴 것

- 바뀐 문구를 쓰는 테스트(`*.test.tsx`, `e2e/`)의 기대 문구 갱신. 위 범위 안에서 옛 이름을 전부 찾아 바꾼다.
- 사전 등록 안내 상자와 포털 이용 중단 안내의 정확한 문장. 대시와 가운뎃점을 쓰지 않고, 범위는 물결표로 잇는다.
- `docs/glossary.md`의 열 순서와 길이. 한 화면에 들어오는 짧은 표면 된다.

## 확인 기준

- `web/`에서 "단원 계정", "계정 목록", "미리 승인", "접근 해제"를 찾았을 때 남아 있지 않다. 세 문서(`operations`, `design-system`, `glossary`)에는 괄호 병기와 변경 기록에만 남는다. 서버 코드와 옛 문서는 검사 대상이 아니다.
- 하위 메뉴, 탭 제목, 페이지 제목이 같은 이름을 쓴다.
- `web`의 vitest, tsc, eslint가 통과한다. 서버 문구를 고쳤다면 `api`의 gradle test도 통과한다.
