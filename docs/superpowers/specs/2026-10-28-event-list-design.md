# 일정 목록 화면과 정기, 비정기 구분 설계

작성일: 2026-10-28. 대상: `event.kind`, 일정 등록과 수정 화면, 단원 메뉴, 새 `/events` 화면, 이달의 일정 아이콘.

## 왜 바꾸는가

단원이 "이번 달 연습이 몇 번이지?"를 알기 어렵다. 정기연습과 비정기연습이 섞여 있고 구분 표시가 없다. 일정은 달력이나 이달의 일정 칸에서만 볼 수 있어, 일정 중심으로 훑어볼 화면이 없다.

#26에서 일정 종류(전체연습, 파트연습, 행사)가 들어왔지만 정기와 비정기는 나누지 않았다. 이달의 일정 아이콘(`EventKind.tsx`)만 제목 단어로 정기와 비정기를 짐작한다. 사용자는 2026-10-28 제목 짐작 대신 등록할 때 고르는 방식을 골랐다('최종 리허설'처럼 제목만으로는 모르는 일정이 있어서).

## 결정한 것

### 종류

| 화면 이름 | 코드 | 파트 | 등록과 수정 권한 |
| --- | --- | --- | --- |
| 정기연습 | `REGULAR_REHEARSAL` | 없음 | 지금 전체연습과 같음(`MANAGE_FULL_REHEARSALS`) |
| 비정기연습 | `EXTRA_REHEARSAL` | 없음 | 지금 전체연습과 같음(`MANAGE_FULL_REHEARSALS`) |
| 파트연습 | `PART_REHEARSAL` | 하나 | 그대로 |
| 중요 행사 | `EVENT` | 없음 | 그대로 |

- `FULL_REHEARSAL`을 `REGULAR_REHEARSAL`과 `EXTRA_REHEARSAL` 둘로 나눈다. 서버(`EventKind`, `EventAccess`)와 웹(`session.ts`의 `canManageEvent`, `canManageRoster`, 등록과 수정 화면)에서 `FULL_REHEARSAL`을 보던 곳은 두 값을 똑같이 다룬다. 권한 이름 `MANAGE_FULL_REHEARSALS`는 그대로 둔다.
- `EVENT` 코드는 그대로 두고 화면 이름만 "행사"에서 "중요 행사"로 바꾼다. 연주회, 발표회, MT 같은 일정이 여기에 들어간다(사용자 결정).
- 선택지 순서는 정기연습, 비정기연습, 파트연습, 중요 행사. 기본값과 일괄 등록의 자동 제목은 지금 방식을 따른다(일괄 등록은 고를 수 있는 첫 종류, 제목은 "정기연습", "비정기연습").

### 마이그레이션 `V8__event_kind_regular.sql`

- CHECK 제약 `ck_event_kind`를 네 값으로 바꾼다.
- `FULL_REHEARSAL`은 제목에 '비정기'가 있으면 `EXTRA_REHEARSAL`, 없으면 `REGULAR_REHEARSAL`로 옮긴다.
- V7이 기존 일정을 모두 `EVENT`로 옮겼으므로, `EVENT` 중 제목에 '연습'이 있고 '파트'가 없는 일정도 같은 규칙으로 옮긴다. 2026-10~11월 연습 11개가 여기에 해당한다.
- 그 밖의 일정('최종 리허설' 등)은 중요 행사로 남는다. 바꿀 일정은 운영진이 수정 화면에서 고친다.

### 일정 목록 화면 `/events`

- 단원 메뉴는 홈(`/dashboard`), 일정(`/events`), 공지, 내 출석 넷이다. 로그인 뒤 첫 화면과 로고 링크는 지금처럼 `/dashboard`(달력, 공지, 내 출석)이다(사용자 결정). 대시보드의 페이지 제목은 "홈"으로 바꾼다.
- 제목은 "다가오는 일정", 오른쪽에 대시보드로 가는 "달력 →" 링크.
- 범위는 오늘(서울 날짜)부터 3달 뒤 달의 말일까지. 기존 `GET /events?from&to`와 `GET /events/rsvps/me`를 그대로 쓴다. 새 API는 만들지 않는다.
- 달마다 묶는다. 달 제목 옆에 그 달 연습 횟수와 종류별 개수 배지를 둔다.
  - 연습 횟수는 정기, 비정기, 파트연습(그 단원에게 보이는 것만)의 합이다. 이번 달은 "남은 연습 N회", 다른 달은 "연습 N회".
  - 배지는 개수가 1 이상인 종류만, 목록 줄의 종류 배지와 같은 색으로 "정기 3", "비정기 4", "중요 행사 1"처럼 쓴다.
- 줄마다 날짜, 요일, 종류 배지, 제목, 시간(`18:00~20:00`), 참석 응답 칩(대상인 일정만: 참석, 불참, 응답 전). 줄을 누르면 `/events/{id}`. 일정에 장소 칸이 없으므로 장소는 넣지 않는다.
- 맨 아래 "지난 일정 보기"를 누르면 오늘 이전 3달 일정을 최신순으로 같은 형식(달 묶음, 횟수 없이) 아래에 붙인다. 한 번만 불러온다.
- 다가오는 일정이 없으면 "다가오는 일정이 없습니다." 로딩은 기존 스켈레톤 컴포넌트를 쓴다.

### 이달의 일정 아이콘

- `EventKindIcon`은 정기, 비정기, 파트연습을 DB 종류로 고른다. 중요 행사만 지금처럼 제목으로 리허설, 공연, MT 아이콘을 고르고, 맞는 단어가 없으면 일정 아이콘을 쓴다.

### 화면 문구

- 대시(—)와 가운뎃점(·)을 쓰지 않는다. 범위는 `~`, 나열은 칸이나 배지로 나눈다.
- 새 CSS는 `web/src/styles/tokens.css` 토큰과 `docs/design-system.md` 규칙을 따른다.

## 하지 않는 것

- 종류로 걸러 보기, 달력 칸의 종류 배지, 장소 칸, 파트연습의 정기와 비정기 구분.
- 기존 화면의 가운뎃점 정리(사용자가 2026-10-28 미룸).

## 확인 방법

- API: 네 종류 모두 등록과 수정이 되고, 정기와 비정기의 권한이 지금 전체연습과 같은지. 옛 값 `FULL_REHEARSAL`은 거절되는지.
- 웹: 달 묶음, 이번 달 "남은", 종류별 개수, 응답 칩, 지난 일정 불러오기, 메뉴 넷과 활성 표시, 등록 화면의 네 선택지.
- 배포 뒤 운영 사이트에서 10~11월 연습이 정기와 비정기로 나뉘어 보이는지.
