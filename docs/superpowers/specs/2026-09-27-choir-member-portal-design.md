# 전남대학교 합창단 회원 포털 설계

작성일: 2026-09-27

## 목적과 범위

첫 구현은 승인된 단원이 공지, 행사 일정, 본인 출석 여부를 확인하고 현장에서 직접 출석하는 회원 포털이다. 운영진은 가입 신청, 공지, 행사와 출석 기록을 관리한다. 공개 온보딩의 시각 디자인은 별도로 설계한다. 공개 행사 아카이브를 추가할 수 있도록 행사에 공개 여부를 두되, 첫 구현에서는 회원 자료를 외부에 노출하지 않는다.

## 사용자와 권한

| 구분 | 할 수 있는 일 |
| --- | --- |
| 방문자 | 공개 온보딩 열람, 가입 신청, 로그인 |
| 가입 신청자 | 본인 신청 상태 확인, 이메일 확인 재요청 |
| 활동 단원 | 회원 공지·행사·본인 출석 열람, 대상 행사 현장 출석 |
| OB | 회원 공지·행사·본인 출석 열람, OB 참여 대상으로 지정된 행사 현장 출석 |
| 운영진 | 가입 승인·반려·접근 해제, 공지·행사 작성과 수정, 출석 창 발급·종료, 출석 정정 |

계정 상태(이메일 확인 전, 승인 대기, 승인, 반려, 접근 해제)와 단원 구분(활동 단원, OB)은 별도로 관리한다. 운영진 권한도 단원 구분과 독립적이다. 모든 권한은 서버에서 검사한다. 첫 운영진 계정은 공개 가입 화면에서 스스로 운영진 권한을 얻을 수 없으며, 배포 시 안전한 관리자 절차로 지정한다.

## 가입과 로그인

1. 신청자는 학교 메일로 제한하지 않은 이메일, 비밀번호, 이름으로 가입을 신청한다.
2. 이메일 확인을 마치면 운영진 승인 대기 상태가 된다. 이메일 확인은 주소 사용 권한을 확인하며 합창단 소속 여부를 대신하지 않는다.
3. 운영진이 보유한 단원 명단이나 기존 운영 방식으로 신청자를 대조하고 활동 단원 또는 OB로 승인하거나 신청을 반려한다. 명단의 존재는 사용자의 예상이며, 실제 승인 담당자와 대조 방법은 운영 시작 전에 운영진과 확인한다. 첫 구현에서 명단 업로드는 요구하지 않는다.
4. 승인 계정만 회원 자료와 출석 기능에 접근한다. 접근 해제 시 기존 로그인 세션도 사용할 수 없게 한다.

비밀번호는 검증된 인증 구성요소로 해시해 저장한다. 로그인 시도 제한, 이메일 확인 링크 만료, 비밀번호 재설정, 서버가 관리하는 세션 만료를 포함한다. 회원 화면에 진입할 때마다 계정 상태를 서버에서 확인한다.

## 화면과 주요 흐름

회원 첫 화면은 **일정 탐색 중심**으로 구성한다. 달력에서 날짜와 행사를 선택하면 행사 상세, 본인의 출석 상태, 출석 가능한 시간의 참여 버튼을 보여준다. 최근 공지 요약과 전체 공지·내 출석 기록으로 가는 경로를 함께 둔다. 모바일에서는 달력 다음에 선택한 행사, 공지, 본인 출석을 세로로 배치한다.

운영진 화면은 가입 신청 목록, 공지 목록·작성·수정, 행사 목록·작성·수정, 행사별 출석 창과 출석 기록을 제공한다. 운영진이 행사마다 활동 단원만 대상인지 OB도 대상인지 지정한다. 행사 공개 여부는 별도로 저장하며 회원에게 보이는 행사와 공개 행사 아카이브의 노출 범위를 구분한다.

## 데이터와 출석 처리

핵심 데이터는 `member`, `notice`, `event`, `attendance`, `check_in_session`, `admin_action_log`이다. `attendance`는 회원과 행사의 조합당 한 건만 유효하게 저장한다. 행사에는 일정, 내용, 대상 단원 구분, 공개 여부를 둔다. 공지는 운영진이 포털에서 직접 작성한다.

운영진은 행사 현장에서 출석 창을 열고 10분 동안 유효한 QR과 입력 코드를 표시한다. 두 방식은 같은 출석 창을 가리키며, 출석 창을 유지하면서 코드를 재발급할 수 있다. 회원이 입력하면 서버는 승인 계정인지, 해당 행사의 출석 대상인지, 출석 창이 유효한지, 이미 출석했는지를 검사한 뒤 기록한다. 출석 창이 닫힌 뒤 미출석 대상자는 미출석으로 표시한다. 운영진은 오입력을 정정할 수 있으며 정정자, 시각, 이전·변경 상태를 남긴다. 지각·공결 등 추가 판정 규칙은 첫 구현에 넣지 않는다.

QR이나 코드는 다른 사람에게 전달될 수 있으므로 이 방식만으로 실제 현장 체류를 증명하지는 않는다. 코드 재발급, 계정·행사 대상 검증, 운영진 정정을 조합해 운영한다. `admin_action_log`에는 가입 승인·반려·접근 해제와 출석 정정의 수행자와 시각을 남긴다. 회원에게는 만료, 대상 아님, 중복 출석, 승인 대기 상태를 구분해 안내한다.

## 코드 구성 방향

웹 프론트엔드와 API 서버를 분리한다. 웹 프론트엔드는 Next.js·TypeScript에서 화면 경로, API 호출, 서버 상태 조회, 공통 컴포넌트를 분리한다. 백엔드는 Spring Boot에서 회원·인증, 공지, 행사, 출석 기능별로 요청 처리, 업무 규칙, 저장소 코드를 분리한다. 관계형 DB에는 버전이 있는 스키마 변경을 적용한다. 구체적인 버전, 인증 라이브러리, 배포 구성은 구현 계획에서 검증해 정한다.

## 검증 기준

- 미승인·접근 해제 계정은 회원 API와 화면 자료에 접근하지 못한다.
- 운영진만 가입 승인, 공지·행사 변경, 출석 정정을 수행한다.
- OB는 OB 참여 대상으로 지정된 행사에서만 출석할 수 있다.
- 만료된 코드, 닫힌 출석 창, 중복 요청은 출석 기록을 추가하지 않는다. 동시 요청에서도 회원·행사당 유효 기록은 한 건이다.
- 회원은 달력에서 행사와 본인 출석 상태를 확인하고, 운영진의 정정 결과를 볼 수 있다.
- 공개 화면과 공개 API에 회원 공지, 비공개 행사, 개인 출석 정보가 노출되지 않는다.
