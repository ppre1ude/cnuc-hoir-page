# 출석 창을 연습 시간에 묶고 지각을 기록하는 설계

작성일: 2026-10-27. 대상: `api/.../attendance/*`, `web/src/features/attendance/*`, 운영진 출석 관리 화면, 단원 출석 화면.

## 왜 바꾸는가

지금까지 연습 출석은 운영진이 눈으로 세고, 카톡 투표에서 "참석"이라 한 사람 중 실제로 온 사람과 늦은 사람을 가려 왔다. 포털의 출석 창은 운영진이 "열기"를 누른 순간부터 10분만 유효하고, 그 뒤에 온 사람은 미출석으로 남아 운영진이 매번 정정해야 한다. 운영진은 연습장에 노트북을 잘 가져오지 않으므로 QR을 공개적으로 띄울 수 없고, 폰에서 숫자 코드를 불러 주는 흐름이 현실적이다.

운영팀은 나중에 지각자를 따로 추려 통계나 벌금 제도에 쓰려 한다(사이트 관리자의 전언, 확정 규정 아님). 그래서 포털은 지각을 기록만 하고, 기준 시간은 상수 하나로 둬 규정이 바뀌면 코드만 고치면 되게 한다.

## 목표

- 운영진이 연습마다 하는 조작을 "출석 받기 한 번 누르고 코드 불러 주기"로 줄인다. 지금보다 누르는 횟수가 늘지 않는다.
- 지각을 운영진 손 안 거치고 자동으로 기록한다.
- 출석·지각 시각을 운영진이 화면에서 바로 본다.
- 출석 코드를 4자리 숫자로 바꿔 소리 내어 불러 주기 쉽게 한다.

## 하지 않는 것

- 파트별 출석, 벌금·통계 화면, 알림 발송.
- 코드를 주기적으로 바꾸는 방식. 코드가 연습 끝까지 살아 있어서 자리에 없는 사람이 숫자를 전달받아 찍을 수 있는 위험은 2026-10-27 사용자가 받아들였다. 운영진이 눈으로 센 결과와 다르면 정정으로 잡는다.
- 창만 따로 늘리는 버튼. 연습이 늦게 끝나면 행사 종료 시각을 고치면 창이 같이 늘어난다(아래 "출석 창의 수명"). 끝난 뒤 온 사람은 정정으로 처리한다.
- QR 방식 변경. QR 주소와 토큰은 지금 그대로 둔다.

## 실패로 보는 것

- 운영진이 연습마다 눌러야 하는 버튼이 지금보다 늘어나는 것.
- 운영진이 그날 출석 관리 화면을 한 번도 열지 않았는데 단원들이 미출석으로 남는 것.
- 연습 시작 한참 전에 찍은 출석이 정시 출석으로 인정되는 것.

## 결정한 것

### 시간 규칙

행사의 `start_at`, `end_at`을 기준으로 한다. 두 상수는 `CheckInService`에 이름 붙여 둔다.

| 구간 | 결과 |
| --- | --- |
| 시작 30분 전 이전 | 거절. 오류 코드 `CHECK_IN_NOT_YET`, 문구는 "출석은 연습 시작 30분 전부터 할 수 있습니다." |
| 시작 30분 전 ~ 시작 15분 뒤 직전 | `CHECKED_IN` (출석) |
| 시작 15분 뒤 ~ 종료 | `LATE` (지각) |
| 종료 뒤 | 거절. 기존 `SESSION_CLOSED` |

- `OPEN_BEFORE = 30분`, `LATE_AFTER = 15분`. 30분은 사이트 관리자의 판단값, 15분은 사용자가 정한 값이다.
- 상태는 출석을 찍는 순간 정해서 `attendance.status`에 저장한다(`CHECKED_IN` / `LATE` / `MISSED`). 나중에 상수를 바꿔도 이미 저장된 기록은 바뀌지 않는다. `attendance.status` 열은 `VARCHAR(16)`이고 CHECK 제약이 없어 마이그레이션 없이 `LATE`를 넣을 수 있다.
- 미출석(`MISSED`) 판정 로직은 지금 그대로다: 창이 닫히거나 만료된 뒤, 창을 열 때 찍은 대상자 스냅샷에 있으면서 출석 기록이 없는 단원.

### 출석 창의 수명

- 창은 행사의 `end_at`까지 산다. 만료 판정은 저장해 둔 `expires_at`이 아니라 행사의 현재 `end_at`으로 한다(`expires_at`에는 만들 때의 `end_at`을 넣어 두되 판정에는 쓰지 않는다). 그래서 운영진이 행사 종료 시각을 늦추면 창도 그만큼 늘어난다. 연습이 늦게 끝날 때는 이렇게 행사 시각을 고치는 것이 의도한 우회다(사이트 관리자의 판단). "재발급"은 코드와 QR 토큰만 바꾼다.
- 창은 운영진이 출석 관리 화면에서 "출석 받기" 버튼을 눌러야 생긴다(기존 `POST /admin/events/{id}/check-in-session`). 화면을 열어 보기만 해서는 아무 일도 일어나지 않는다. 2026-10-27 사용자가 고른 방식이다: 파트연습처럼 출석을 안 받는 일정의 명단을 구경하다가 전원이 미출석으로 남는 일을 막는다.
- 열기는 `start_at - 30분` 이후 `end_at` 이전에만 허용한다. 그 밖의 시각에 누르면 거절한다(오류 코드 `SESSION_NOT_YET` / 기존 `SESSION_CLOSED`). 시작 30분 전 이전에는 버튼을 꺼 두고 "출석 창은 오후 5:30부터 열 수 있습니다"처럼 열 수 있는 시각을 보여 준다. 더 일찍 여는 길은 두지 않는다(사이트 관리자의 판단: 코드를 미리 보면 카톡으로 돌릴 수 있어 현장 증명의 뜻이 없어진다).
- 별도 타이머나 스케줄러는 두지 않는다. 열린 시각과 상관없이 출석·지각 판정은 행사 시각 기준이다.
- 운영진이 "닫기"를 누르면 지금처럼 닫히고, 같은 화면에 "다시 열기"가 보인다. 다시 열기도 같은 POST이며 같은 시간 구간 안에서만 허용한다.
- 배포 전에 연 창은 V6 마이그레이션이 옛 만료 시각에 닫은 것으로 적는다. 배포 순간 열려 있던 창도 닫히므로, 연습 중이었다면 운영진이 "다시 열기"를 눌러 4자리 코드를 새로 받는다.

### 코드

- 4자리 숫자(`0000`~`9999`), `SecureRandom`. 영문은 쓰지 않는다.
- 운영진이 언제든 현재 코드를 봐야 하므로 코드는 해시가 아니라 평문으로 저장한다. `check_in_session`에 `code VARCHAR(8)` 열을 추가하는 마이그레이션을 쓴다. 4자리 숫자의 해시는 어차피 1만 번 안에 풀리므로 해시가 주는 보호가 없다. QR 토큰은 지금처럼 해시로 둔다.
- 코드 검증은 저장된 평문과 비교한다. 시도 제한(계정당 1분 10회, IP당 1분 100회)은 그대로 둔다.
- 단원 입력칸은 `maxLength=4`, `inputMode="numeric"`, `pattern="\d{4}"`, 자동 대문자 끄기. 서버의 `CredentialInput`은 QR 토큰도 받으므로 길이 제한은 그대로 둔다.

### 운영진 출석 관리 화면

- 창이 열려 있으면 현재 코드를 크게 보여 준다. 유효 시간 문구는 "연습 끝(오후 8:00)까지"처럼 종료 시각으로 바꾼다. "10분 동안 유효", "회전하면 이전 코드는 즉시 사용할 수 없습니다" 문구는 뜻이 맞게 고친다.
- 창이 없으면 "출석 받기" 버튼을 보여 준다. 아직 열 수 있는 시간이 아니면 버튼을 끄고 열 수 있는 시각을 보여 준다. 닫혀 있으면 "다시 열기"를 보여 준다. "파트연습에는 출석 창을 열지 마세요" 안내는 유지한다.
- 단원별 상태에 출석·지각 시각을 배지 옆에 붙인다(예: `출석 완료 · 오후 6:03`, `지각 · 오후 6:21`). 정정된 기록은 정정됨을 알 수 있게 표시한다(`corrected_at`이 있으면).
- 정정 선택지는 출석·지각·미출석 셋이다. `CorrectionInput`의 정규식에 `LATE`를 더한다. 정정으로 출석·지각을 넣을 때 `checked_in_at`은 지금처럼 정정 시각이다.

### 단원 화면

- 상태 라벨에 `LATE: "지각"`을 더한다. 배지 색은 출석 완료 긍정, 미출석 오류, 지각 중립이다(사이트 관리자의 판단).
- 행사 상세, 출석하기 화면, 내 출석 기록, 대시보드의 내 출석 카드 모두 같은 라벨 표를 쓰므로 한 곳만 고친다.
- 시작 30분 전 이전에 출석을 시도하면 서버 문구를 그대로 보여 준다.

### 문서

- `docs/operations.md`와 `CONTEXT.md`의 출석 절차 설명에서 "10분"을 새 규칙으로 바꾼다.

## 테스트에 대한 주의

- `CheckInFlowTest`는 시계를 `2026-09-27T10:00:00Z`에 고정하고, 기본 행사를 `09:00~12:00`으로 만든다. 새 규칙에서는 10:00이 시작 60분 뒤라 기존 출석이 전부 지각이 된다. 기본 행사 시각을 10:00 근처로 옮기거나, 정시·지각·너무 이름·종료 뒤를 각각 만드는 보조 함수를 둔다.
- 새로 확인할 것: 네 구간 각각의 결과, 열기가 구간 밖에서는 거절되는 것, 행사 종료 시각을 늦추면 창도 늘어나는 것, 재발급이 코드만 바꾸는 것, 정정으로 `LATE`를 넣을 수 있는 것, 내 출석 목록에 `LATE`가 나오는 것.

## 빌더에게 맡기는 것

- 마이그레이션 파일 이름과 위치(어느 폴더가 실제로 쓰이는지 확인).
- 정확한 화면 문구. 화면 문구에 대시(—)를 쓰지 않고 범위는 `~`로 쓴다.
- 창이 열릴 시각과 코드를 운영진 화면에 어떻게 배치할지. 공통 컴포넌트와 토큰(`docs/design-system.md`)을 따른다.
- 시각 표시 형식. 기존 `seoulDateTime`류를 재사용한다.
