# 단원 직책·권한 체계 설계

작성일: 2026-10-03

## 목적과 범위

지금은 회원에게 `admin` 참/거짓과 활동/OB 구분만 있고, 운영진 기능이 모두 `admin` 하나로 열린다. 합창단의 실제 조직(단장단, 부서, 수석진)에 맞춰 회원에게 직책과 파트를 두고, 기능마다 어느 직책부터 열지 정한다. 이 바탕 위에 전체연습·파트연습 구분과 파트연습 참여 조사, 집행부 회의록을 더한다.

실제 사람 이름, 학과, 학번 같은 개인정보는 코드와 문서에 넣지 않는다.

## 조직 구조

안내문에 따른 구성이다.

- **집행부**
  - 단장단: 단장, 부단장, 총무
  - 기획·홍보부: 부장, 부원(기획계), 부원(홍보계)
  - 관리부: 부장, 부원(악보계), 부원(비품계)
- **수석진**: 소프라노수석, 알토수석, 테너수석, 베이스수석, 피아노수석

한 사람이 직책을 여러 개 가질 수 있다. 예를 들어 부단장이 소프라노수석을 겸하거나, 부장이 알토수석을 겸한다.

## 회원 정보

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 단원 구분 | 활동 단원, OB | 지금 그대로 |
| 파트 | 소프라노, 알토, 테너, 베이스, 피아노, 미지정 | 새로 추가 |
| 기수 | 양의 정수 또는 없음 | 새로 추가 |
| 사이트 관리자 | 참/거짓 | 지금의 `admin`을 그대로 쓴다. 직책과 별개다 |

직책 목록은 코드에 고정한다. 부서나 계가 바뀌면 코드와 함께 바꾼다.

| 직책 | 추가 정보 |
| --- | --- |
| 단장 | |
| 부단장 | |
| 총무 | |
| 부장 | 부서(기획·홍보부, 관리부) |

## 권한

서버가 회원의 사이트 관리자 여부와 직책 목록을 보고 "할 수 있는 일" 목록을 만든다. 로그인 응답(`/auth/me`)에 직책 목록과 권한 목록을 함께 내려 주고, 화면은 그 목록으로 메뉴와 버튼을 보여 준다. 모든 권한은 서버에서 다시 검사한다.

| 할 수 있는 일 | 사이트 관리자 | 단장 | 부단장 | 총무·부장·부원 | 수석 | 활동 단원 | OB |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 사이트 관리자 지정·해제, 단장·부단장 지정·해제, 사이트 관리자 등록 명단 관리 | ○ | | | | | | |
| 그 밖의 직책 부여·해제, 파트·기수 수정, 접근 해제, 자동 승인 명단 관리 | ○ | ○ | | | | | |
| 가입 승인·반려, 1회용 링크 발급 | ○ | ○ | ○ | | | | |
| 전체연습 개최·수정 | ○ | ○ | ○ | | | | |
| 모든 파트의 파트연습 개최·수정과 참여 집계 열람 | ○ | ○ | ○ | | | | |
| 자기 파트의 파트연습 개최·수정과 참여 집계 열람 | | | | | ○ | | |
| 행사 등록·수정, 공지 등록·수정, 출석 창 열기·닫기, 출석 정정 | ○ | ○ | ○ | ○ | ○ | | |
| 회의록 쓰기·고치기 | ○ | ○ | ○ | ○ | ○ | | |
| 회의록 삭제 | ○ | | | | | | |
| 회원 목록 보기(이름, 파트, 기수, 직책) | ○ | ○ | ○ | ○ | ○ | | |
| 회의록 보기 | ○ | ○ | ○ | ○ | ○ | ○ | |
| 일정·공지 보기, 참석 응답, 현장 출석, 투표 | ○ | ○ | ○ | ○ | ○ | ○ | ○(OB 대상 행사만) |

- 겸임이면 가진 직책 권한의 합이다.
- 사이트 관리자는 직책이 없어도 모든 권한을 가진다.
- 수석은 자기 파트의 파트연습만 다룬다. 피아노수석은 피아노 파트연습을 열 수 있지만 파트원이 없으면 쓸 일이 없다.
- 지금의 "운영진 사전 등록"은 사이트 관리자 등록 명단이 된다. 등록된 이메일로 첫 로그인하면 사이트 관리자가 된다. 일반 직책은 로그인한 뒤 회원 목록에서 부여한다.
- 기존 `admin` 계정은 그대로 사이트 관리자가 된다. 직책은 비어 있으므로 배포 뒤 사이트 관리자가 직접 부여한다.

## 행사 종류와 파트연습

- 행사마다 종류를 둔다: **전체연습**, **파트연습**(파트 지정), **행사**(공연, 워크숍, 환영회 등). 기존 행사는 모두 "행사"로 옮긴다.
- 파트연습은 해당 파트 단원, 집행부, 수석진에게만 보인다. 다른 파트 단원의 일정과 출석 대상에는 나오지 않는다. OB 참여 대상 표시는 파트연습에도 그대로 적용된다.
- 참여 조사는 지금의 참석/불참 응답을 그대로 쓴다. 파트연습 응답 집계(참석·불참·미응답 인원과 명단)는 그 파트의 수석, 단장단, 사이트 관리자가 본다.
- 전체연습과 행사의 응답 집계는 지금처럼 행사·공지 등록 권한이 있는 사람이 본다.
- 일괄 등록은 종류를 함께 고르며, 파트연습 일괄 등록도 같은 권한 규칙을 따른다.

## 회의록

- 항목: 제목, 회의 일시, 본문, 작성자, 마지막 수정자와 시각.
- 본문은 공지처럼 일반 글이며 줄바꿈을 유지한다. 파일 첨부와 서식 편집기는 넣지 않는다.
- 목록은 회의 일시 최신순이다. 활동 단원은 회원 메뉴 "회의록"에서 보고, 집행부·수석진은 같은 화면에서 쓰고 고친다. 삭제는 사이트 관리자만 한다.
- OB에게는 메뉴와 목록을 보여 주지 않는다. OB에게도 열려면 권한 표만 바꾼다.
- 글 쓴 사람은 바뀌지 않고, 고칠 때마다 마지막 수정자와 시각을 덮어쓴다. 화면에 둘을 함께 보여 준다. 수정과 삭제는 운영 기록에 행위만 남기고 본문은 남기지 않는다. 이전 판은 보관하지 않으며, 되돌리기가 필요해지면 그때 이전 판 테이블을 더한다.

## 화면

- **회원 메뉴**: 일정, 공지, 회의록, 내 출석. 권한이 하나라도 있으면 "운영진"이 추가된다.
- **단원 계정(운영진)**: 회원 행마다 파트, 기수, 직책을 보여 주고 고친다. 직책은 목록에서 골라 추가하며, 부장·부원·수석은 부서·계·파트를 함께 고른다. 단장·부단장 지정과 사이트 관리자 지정은 사이트 관리자에게만 보인다.
- **행사 관리**: 종류를 고르고, 파트연습이면 파트를 고른다. 수석은 자기 파트의 파트연습만 목록에 보이고 만들 수 있다.
- **파트연습 집계**: 행사 관리의 응답 집계에 파트 기준 명단이 그대로 나온다. 별도 화면은 만들지 않는다.
- **회의록**: 목록과 상세, 쓰기·고치기 폼. 공지 관리 화면의 구성을 따른다.
- 권한이 없는 기능은 메뉴와 버튼을 숨기고, 서버는 403으로 거부한다.

## 자료 구조

- `member`에 `part`, `cohort` 열을 더한다. `admin` 열은 사이트 관리자 뜻으로 유지한다.
- `member_role`: 회원, 직책, 부서, 계, 파트, 부여한 회원, 부여 시각. 회원·직책·부서·계·파트 조합에 고유 제약.
- `event`에 `kind`(전체연습·파트연습·행사)와 `part` 열을 더한다. 기존 행은 "행사"로 채운다.
- `meeting_minutes`: 제목, 회의 일시, 본문, 작성자, 마지막 수정자, 생성·수정 시각.
- 직책 부여·해제, 파트·기수 수정, 회의록 삭제는 지금의 운영 기록(`admin_action_log`)에 남긴다.

## 구현 순서

각 단계는 따로 배포할 수 있다.

1. 회원 정보·직책·권한: DB 열과 테이블, 권한 계산, `/auth/me` 응답, 기존 `requireAdmin`을 권한별 검사로 교체, 단원 계정 화면의 직책 부여, 메뉴 표시.
2. 행사 종류와 파트연습: `event` 열 추가, 조회 필터, 행사 관리 화면의 종류·파트 선택, 수석 권한.
3. 회의록: 테이블, API, 회원 화면과 쓰기 폼.

## 확인 방법

- API: 직책 조합별로 허용·거부를 확인하는 테스트. 겸임 계정, 수석의 다른 파트 거부, OB의 파트연습 거부, 사이트 관리자 전용 기능의 단장 거부를 포함한다.
- 화면: 권한 목록에 따라 메뉴·버튼이 숨고 나타나는 웹 테스트.
- 목업 데이터로 사이트 관리자, 단장, 수석, 일반 단원 계정의 화면을 1440px와 390px에서 캡처해 비교한다.
- 실제 구글 로그인과 운영 API 검증은 배포 뒤 사이트 관리자 계정으로 한다.

## 하지 않는 것

- 부서·계·직책 목록을 화면에서 편집하는 기능.
- 회의록 파일 첨부, 서식 편집, 댓글, 이전 판 보관과 되돌리기.
- 파트연습 전용 화면이나 알림.
- 직책별로 다른 공지 노출 범위.
