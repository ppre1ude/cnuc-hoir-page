# 무대 페이지 설계

2026-11-26

## 왜 만드나

합창단은 연주회 예고(`/concert`)나 연주회 기록(`/gallery`) 같은 페이지를 앞으로도 계속 만든다. 그런데 이런 페이지를 한곳에서 찾아볼 데가 없다. 공개 메인 머리글에 "무대"를 두고, 누르면 합창단이 지나온 행사를 연도별로 보는 페이지로 가게 한다.

참고한 곳은 에코노베이션 포트폴리오(https://econovation.kr/portfolio/dev)다. 왼쪽에 큰 글자 목록, 오른쪽에 고른 항목의 본문이 있는 배치다. 느낌만 빌리고, 구역 나눔과 글자 위계는 우리 디자인 시스템을 따른다.

창단식 같은 초기 행사나 작은 행사는 남은 자료가 거의 없다. 그래서 **페이지가 있는 행사만 크게** 다루고, 나머지는 연도 안의 한 줄로 둔다.

이름은 `news`나 "소식"이 회사 공식 홈페이지 같아서, 음악 동아리답게 **"무대"**로 정했다. "시즌"은 앞으로의 공연 일정으로 오해할 수 있고, "걸어온 길"은 음악 느낌이 적고, "악장"은 머리글에서 안에 무엇이 있는지 알 수 없어 뺐다.

## 목표

- 공개 메인 머리글에 "무대" 링크를 둔다.
- `/stage` 한 페이지에 모든 행사를 연도별로 보여 준다.
- 페이지가 있는 행사는 고를 수 있는 큰 항목이다. 고르면 오른쪽에 사진, 소개 글, 사실 정보, 페이지 링크가 나온다.
- 휴대폰에서도 같은 내용을 한 열로 본다.

## 하지 않는 것

- 행사 자료를 Supabase에 저장하거나 운영진 화면에서 쓰기.
- 행사 페이지 주소 옮기기. `/concert`, `/gallery`는 그대로 둔다.
- `/gallery`를 회차별로 나누기. 제3회 사진이 생길 때 한다. 사진은 이미 회차별 폴더(`concert-photos/2/`)에 있어 그때 `/gallery/3` 꼴로 나누기 쉽다.
- 스크롤하면 저절로 항목이 바뀌는 효과. 지금은 고를 수 있는 행사가 하나뿐이라 효과가 보이지 않는다. 여럿 쌓이면 다시 본다.
- 공개 메인 05 장면("우리가 걸어온 길") 모양 바꾸기. 같은 자료를 계속 쓸 뿐이다.

## 실패로 보는 것

이 중 하나라도 있으면 동작해도 실패다.

- `tokens.css`에 없는 색, 글자 크기, 간격, 모서리 값을 새로 쓴다.
- 사진이 없는 행사에 빈 사진 칸이 생긴다.
- 합창단이 쓰지 않은 소개 글이 들어간다.
- 오른쪽 본문의 값 글자가 `--text-body`보다 작다. 지난 시안은 14~16px이라 작다는 지적을 받았다.

## 제약

- 색, 크기, 간격은 `web/src/styles/tokens.css` 토큰만 쓴다. 부품은 `components/ui`(`PageHeader`, `Section`, `List`, `Row`, `ActionLink`, `BrandLogo`)를 쓴다.
- 공개 페이지 관례를 따른다. 페이지 맨 바깥에서 글꼴을 Paperlogy(`--font-paperlogy`)로, 굵기를 `--weight-heading: var(--weight-public-heading)` 식으로 바꿔 끼운다(`SandLanding.module.css`, `LoginPoster.module.css`와 같은 방식). 그래서 부품을 고치지 않고 그대로 쓴다.
- 화면 문구는 이미 쓰고 있는 문구만 쓴다. 새 문구는 "무대" 하나다. 소개 글은 합창단이 직접 써서 준다.
- 제목과 버튼에 숫자(사진 장수 등)를 붙이지 않는다. 대시(—)와 가운뎃점(·)은 쓰지 않는다.
- 로그인 없이 누구나 본다.

## 접근 방식

세 가지를 놓고 **1번을 골랐다.**

1. **한 페이지 `/stage`, 자료는 코드 안에 (고름).** 자료는 `features/onboarding/newsItems.ts`에 칸을 더해 둔다. 고르기는 페이지 안에서만 한다. 단점은 소개 글을 고치거나 새 행사를 넣을 때 커밋해야 한다는 것이다. 행사는 1년에 몇 번뿐이라 감당할 만하다.
2. **행사 페이지를 무대 아래로 옮기기.** `/stage/concert-2026`에 초대장, `/stage/concert-2026/photos`에 갤러리를 두는 식이다. 주소는 가장 깔끔하지만, 이미 카톡으로 퍼진 `/concert`, `/gallery`를 옮기고 넘겨주기 설정을 해야 한다. 일이 1번의 두세 배다.
3. **Supabase 표와 운영진 작성 화면.** 회장이나 관리자가 직접 글과 사진을 넣는다. 표, 권한, 작성 화면, 사진 올리기까지 만들어야 해서 가장 크다. 1년에 몇 번 쓰는 기능치고 무겁다.

## 정한 것

### 주소와 고르기

- 주소는 `/stage`다.
- 세부 내용이 있는 행사의 이름은 버튼이고, 행 전체를 누를 수 있다. 누르면 주소는 그대로 두고 페이지 안에서 본문만 바꾼다(에코노베이션처럼). 고른 항목에는 `aria-current="true"`를 달고 이름을 `--color-primary` 글자로만 표시한다. 운영진 화면의 고른 행 모양(초록 세로선, `--color-selected` 바탕)은 공개 페이지에 쓰지 않는다(2026-11-26 사용자 피드백).
- 처음 열면 세부 내용이 있는 가장 최근 행사가 골라져 있다.
- 처음에는 `?event=<id>` 주소로 골랐으나 뺐다. 공유할 일이 거의 없고, 고를 때마다 방문 기록이 쌓여 뒤로 가기가 이전 선택으로 돌아가며, 페이지를 미리 만들어 둘 수 없었다.

### 머리글

- 데스크톱(761px 이상): 로고, 무대, 지원하기, 단원 로그인을 한 줄에 둔다.
- 휴대폰(760px 이하): 로고와 오른쪽 메뉴 버튼만 둔다. 버튼을 누르면 무대, 지원하기, 단원 로그인이 든 메뉴가 열린다(참고: brainworks.co.kr 휴대폰 머리글). 375px 폭에서 로고와 두 버튼 뒤에 남는 자리가 34px뿐이라 링크 셋을 한 줄에 둘 수 없었다.
- 휴대폰에서는 "지원하기"가 메뉴 안으로 들어간다. 마지막 장면의 큰 지원 버튼은 그대로 있다.
- 메뉴는 브라우저 기본 popover 기능으로 만든다. Esc와 바깥 누르기로 닫히고, 새 라이브러리는 없다. 메뉴 버튼의 화면 읽기용 이름은 "메뉴"다.
- 공개 메인과 `/stage`가 같은 링크 묶음 부품을 쓴다. `/stage`에서는 "무대"에 `aria-current="page"`를 단다.

### 화면 구조 (데스크톱)

```
[로고]                          무대   지원하기   단원 로그인
무대                                   ← PageHeader, --text-display

2026 ─────────────────────┐  ┌ 사진 3:2, --radius-panel ┐
제2회 정기연주회     11. 20 │  │                          │
  (고른 행)                 │  └──────────────────────────┘
중앙동아리 승격      09. 29 │  제2회 정기연주회      ← --text-title
5기 단원 입단        09. 03 │  [소개 글]             ← --text-section, 있을 때만
2025 ─────────────────────┤  일시 │ 2026. 11. 20. (금) 19:00
정기연주회 개최      09. 12 │  장소 │ 전남대학교 민주마루   ← 2열 격자
2024 ─────────────────────┤  지휘 │ 박찬영, 박예영
합창단 창단식        12. 06 │  [공연 사진 보기] [초대장 보기]  ← ActionLink large
```

- **폭과 여백:** 최대 폭 `--layout-public`, 좌우 `--page-gutter`, 위 `--page-top`, 아래 `--page-bottom`.
- **두 칸:** 왼쪽 목록 5, 오른쪽 본문 7의 비율. 사이 `--space-16`. 오른쪽 본문은 스크롤해도 따라 내려온다(sticky).
- **연도 구역:** 한 해가 `Section` 하나다. 최신 해가 맨 위다. 연도 제목은 `Section` 제목(`--text-section`) 그대로이고, 그 아래 `List`의 2px `--color-ink` 선이 구역을 나눈다.
- **모든 줄:** `Row`. 이름과 날짜 모두 `--text-body`이고, 날짜는 `--color-muted`. 글자는 연도 제목, 구분선과 같은 왼쪽 선에 맞춘다. 크게 보여 주는 것은 오른쪽 본문 제목이다.
- **큰 항목 (페이지가 있는 행사):** 이름을 `--weight-label`로 굵게 두고 링크로 고른다.
- **작은 줄 (페이지가 없는 일):** 이름은 보통 굵기. 고를 수 없고 사진 칸도 없다.

### 오른쪽 본문

위에서부터 이 순서다.

| 자리 | 모양 |
|---|---|
| 대표 사진 | 가로세로 3:2, `--radius-panel` |
| 이름 | `--text-title`, `--weight-heading` |
| 소개 글 | `--text-section`, `--weight-body`. 글이 있는 행사에만 나온다 |
| 사실 정보 | 상자 없는 2열 격자(`dl`). 칸마다 위에 `--color-line` 1px 선, 항목 이름 `--text-label` 회색, 그 아래 값 `--text-body`(참고: 위그모어 홀 지난 공연). 운영진용 `Facts` 부품은 쓰지 않는다 |
| 페이지 링크 | `ActionLink size="large"`. 첫 링크는 주요, 나머지는 `variant="secondary"` |

사이 간격은 `--space-*` 토큰에서 고른다.

### 휴대폰 (760px 이하)

- 한 열로 쌓는다. 오른쪽 본문 칸은 없다.
- 고른 큰 항목만 이름 바로 아래에 사진, 소개 글, 사실 정보, 링크를 펼친다. 다른 큰 항목을 누르면 그 항목이 펼쳐진다. 데스크톱과 같은 고르기 규칙이라 처음에는 가장 최근 큰 항목이 펼쳐져 있다. 지금은 큰 항목이 하나뿐이라 늘 펼쳐져 보인다. 휴대폰에서는 사진을 화면 좌우 끝까지 넓히고, 사실 정보는 2열 격자를 그대로 둔다.
- 작은 줄은 그대로 한 줄이다.

### 자료

`PublicNewsItem`에 선택 칸 `detail`을 더한다. `detail`이 있으면 무대에서 고를 수 있는 행사, 없으면 연도 안의 한 줄이다. "전용 페이지가 있다"(links)와 "세부 내용이 있다"(detail)를 한 칸에 묶지 않는다(2026-11-26 사용자 피드백: 제1회처럼 페이지 없는 행사도 세부 내용을 가져야 함).

```ts
type PublicNewsItem = {
  id: string;
  date: string; // YYYY-MM-DD
  title: string; // 이름은 이 칸 하나. "개최"를 붙이지 않는다. 공개 메인 05 장면도 같은 이름을 쓴다.
  description?: string;
  link?: { href: string; label: string }; // 공개 메인 05 장면용, 그대로 둔다
  detail?: {
    photo?: { src: string; width: number; height: number; alt: string };
    lead?: string; // 합창단이 쓴 소개 글
    facts?: { label: string; value: string }[];
    links?: { href: string; label: string }[]; // 전용 페이지. 첫 링크가 주요 버튼
  };
};
```

칸은 모두 선택이고, 없는 칸은 화면에 자리도 만들지 않는다(사진 없으면 사진 칸 없음, 링크 없으면 버튼 없음).
2026-11-26 추가: `subtitle`(공연 이름, 행사 이름 바로 아래 `--text-section` 회색)과 `program`(부마다 곡 목록, 곡 아래 설명은 `--text-label` 회색). 프로그램은 사실 정보와 같은 꼴로 부마다 위에 가는 선을 긋고, 데스크톱은 부를 2열로, 휴대폰은 위아래로 둔다. 제2회 프로그램은 아직 받지 못했다.

지금 자료:

- `concert-2026` "제2회 정기연주회": 갤러리 표지와 같은 195번 사진(`hallPhoto`), 일시 "2026. 11. 20. (금) 19:00", 장소 "전남대학교 민주마루", 지휘 "박찬영, 박예영", 링크 "공연 사진 보기"(`/gallery`), "초대장 보기"(`/concert`). 값은 `concert.ts`에서 가져오지 않고 옮겨 적는다(다음 연주회가 정해지면 그 파일이 바뀐다).
- `concert-2025` "제1회 정기연주회": 일시 "2025. 9. 12. (금)", 장소 "전남대학교 예술대학 3호관 예향홀". 시작 시각, 지휘, 사진은 받으면 채운다.
- `lead`: 합창단이 글을 주면 넣는다. 그전에는 비워 둔다.

## 만드는 사람에게 맡기는 것

- 사진을 `next/image`로 그릴지. 갤러리는 `unoptimized`로 쓰고 있다.
- 날짜 표기 함수. 공개 메인 05 장면에 이미 있으면 그것을 쓴다.
- 휴대폰에서 본문을 펼치는 방법(같은 내용을 두 번 그리고 CSS로 숨길지 등).
- `historyByYear()`를 그대로 쓸지, 처음 고를 행사를 정하는 함수를 따로 둘지. 그 규칙(세부 내용이 있는 가장 최근 행사)에는 시험을 하나 둔다.

## 확인 방법

- 개발 서버에서 `/stage`를 데스크톱과 휴대폰 폭으로 캡처한다.
- `/stage`가 제2회 정기연주회를 고른 상태로 열리고, 제1회를 누르면 주소가 바뀌지 않은 채 본문만 바뀌는지 본다.
- 새 CSS 파일에 토큰이 아닌 색, px 값이 없는지 확인한다.
- `npm run lint`, `npx tsc --noEmit`(전에 `next typegen`), `npx vitest run`이 통과한다.
