# 운영진 계정 발급 스펙

작성일: 2026-09-29. 공개 가입과 이메일 확인·재설정 대신 운영진이 명단을 확인하고 계정을 발급한다.

## 사용자 흐름

1. DB 관리자가 최초 운영진을 비공개 명령으로 초대한다. 초대 계정은 비밀번호가 없고 로그인할 수 없다.
2. 운영진이 `/admin/members`에서 단원의 이름, 로그인 이메일, 활동 단원·OB 구분을 입력한다. 서버는 `INVITED` 계정과 1회용 설정 토큰을 만들고 원문을 응답에 한 번만 반환한다.
3. 운영진이 명단의 해당 단원에게 링크를 비공개로 전달한다. 단원은 `/activate`에서 비밀번호를 직접 설정한 뒤 로그인한다.
4. 링크가 만료되거나 비밀번호를 잊으면 운영진이 동일 계정에 새 링크를 발급한다. 이전 미사용 링크는 무효가 된다.
5. 운영진이 접근을 해제하면 기존 세션과 로그인 권한이 사라진다.
6. 접근 해제된 단원이 다시 활동하면 운영진이 같은 계정을 다시 초대할 수 있다. 이전 비밀번호는 지워진다.

## 보안 규칙

- 계정 생성·링크 재발급·목록 조회·접근 해제는 운영진 세션과 CSRF 검사를 통과해야 한다.
- 초대 토큰은 32바이트 보안 난수이며 해시만 DB에 저장한다. 24시간 뒤 만료되고 사용 뒤 재사용할 수 없다.
- 토큰은 URL 조각(`#token`)으로 전달하고 설정 화면은 브라우저 주소에서 즉시 지운다. API 응답은 캐시하지 않는다.
- 단원은 비밀번호를 직접 설정한다. 비밀번호 변경은 `authVersion`을 올려 기존 세션을 무효화한다.
- 가입 신청·이메일 확인·메일 재설정 공개 API는 제공하지 않는다. 이메일은 로그인 아이디이며 주소 소유 확인을 의미하지 않는다.
- 초대 링크는 발급 직후 한 번만 표시한다. 전달 전에 운영진이 사람과 명단을 대조해야 한다.

## 완료 기준

- 운영진만 계정을 만들고 링크를 재발급할 수 있다.
- 초대 전 계정은 로그인할 수 없고, 링크 재발급 뒤 구 링크·사용한 링크는 거부된다.
- 단원 계정 설정 뒤 로그인과 권한 조회가 가능하다.
- 재설정 후 기존 세션은 무효화된다.
- 메일 서비스 없이 API가 기동하고 웹 빌드·테스트가 통과한다.
- 실제 공개 주소·API·DB에서 운영진 초대와 단원 로그인·투표를 시범 검증하기 전까지 배포 완료로 표시하지 않는다.
