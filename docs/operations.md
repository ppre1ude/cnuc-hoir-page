# 회원 포털 운영 절차

## 배포 전 결정

운영진은 최신 단원 명단의 관리 담당자와 대조 방법, 첫 운영진으로 초대할 사람, 개인별 초대 링크를 전달할 비공개 채널을 정합니다. 명단과 초대 링크는 저장소에 넣지 않습니다. 미리보기 구성은 Vercel 웹, Render API, Supabase PostgreSQL입니다. 실제 공개 HTTPS 주소는 각 서비스 생성 뒤 확정합니다.

## 운영 전환 순서

1. 운영진이 명단을 확인하고 첫 운영진의 이름·로그인 이메일·단원 구분을 확정합니다.
2. 배포 담당자가 API·PostgreSQL의 비밀값과 공개 HTTPS 주소를 설정하고 `.\deployment\check-launch-config.ps1 -PublicOrigin https://확정한-도메인`을 실행합니다. 배포 뒤 `-CheckLive`로 공개 화면과 `/api/v1/auth/csrf`를 확인합니다.
3. 운영 DB 변경 전에 일관된 백업을 남기고, 격리 환경에서 복구와 Flyway 마이그레이션, 회원·행사·출석·감사 기록 조회를 확인합니다. 이미 적용된 마이그레이션 파일은 수정하지 않습니다.
4. DB 접속 권한을 가진 배포 담당자가 API 프로젝트에서 `gradlew.bat bootstrapAdminInvite --args="<JDBC URL> <DB 사용자> <이메일> <이름> ACTIVE"`를 실행합니다. DB 비밀번호는 콘솔 또는 일시적인 `CHOIR_BOOTSTRAP_DB_PASSWORD`로 공급합니다. 이 명령은 운영진 계정이 이미 있으면 거절합니다. 출력된 1회용 토큰을 실제 HTTPS 주소의 `/activate#token=<토큰>`에 붙여 첫 운영진에게 비공개로 전달합니다. 공유 로그나 작업 티켓에 토큰을 남기지 않습니다.
5. 첫 운영진이 24시간 안에 비밀번호를 직접 설정하고 로그인합니다. 이후 `/admin/members`에서 명단과 대조한 단원의 이름, 이메일, 활동 단원·OB 구분을 입력해 개인별 초대 링크를 발급합니다.
6. 단원은 링크에서 비밀번호를 설정한 뒤 로그인합니다. 링크는 한 번만 표시되고 한 번만 사용할 수 있습니다. 만료 또는 분실 시 운영진이 새 링크를 발급하며 이전 링크는 무효가 됩니다. 비밀번호를 잊은 단원도 운영진에게 본인 확인을 요청해 새 계정 설정 링크를 받습니다. 접근 해제된 단원이 복귀하면 같은 계정을 다시 초대할 수 있으며 이전 비밀번호는 지워집니다.
7. 실제 접속 경로에서 TLS, `Secure` 세션 쿠키, CSRF, 권한 경계, 프록시 전달 IP 위조 차단과 공용망 출석 시도 제한을 확인합니다. 소수 단원으로 공지·투표·행사·QR·코드 출석과 정정을 시범 수행합니다.

각 단계의 담당자와 날짜, 결과를 운영 기록에 남깁니다. 2026-09-30 현재 Vercel 웹은 배포되었지만 API 경로는 404를 반환합니다. Render API와 Supabase DB를 연결한 뒤 회원 기능을 검증해야 합니다.

## 계정과 권한

공개 가입 신청과 이메일 재설정은 사용하지 않습니다. 이메일 주소는 로그인 아이디로만 사용하며 소유 확인을 뜻하지 않습니다. 합창단 소속 여부는 운영진이 명단으로 확인합니다. 초대 계정은 비밀번호를 설정하기 전까지 로그인할 수 없습니다. 새 링크 발급은 같은 계정의 이전 미사용 링크를 무효화합니다. 비밀번호 재설정 후 기존 세션은 무효화됩니다. 접근 해제된 계정은 다시 로그인할 수 없습니다.

초대 토큰 원문은 DB에 저장하지 않고 SHA-256 해시만 저장합니다. 링크 원문은 발급 응답과 첫 운영진 초기화 명령에서 한 번만 확인할 수 있습니다. 링크를 전달받는 사람을 잘못 선택하면 계정에 접근할 수 있으므로, 운영진은 전달 전에 본인을 확인해야 합니다. 비밀번호는 12자 이상, UTF-8 기준 72바이트 이하입니다.

## 환경과 네트워크

`.env.example`은 변수 이름만 보여 줍니다. 실제 비밀번호는 저장소와 셸 기록에 남기지 않고 실행 환경의 비밀 저장소에서 공급합니다. 개발용 `compose.yaml`은 PostgreSQL만 루프백에 엽니다. `compose.portal.yaml`은 로컬 검증용 HTTP 프록시만 루프백에 노출합니다. 운영 환경에서는 HTTPS를 적용하고 쿠키의 `HttpOnly`, `Secure`, `SameSite=Lax`를 유지합니다. 배포 인그레스가 정해지면 신뢰 프록시 CIDR과 실제 접속 IP 전달·위조 차단을 다시 검증합니다.

## 행사와 출석 현장 대응

운영진은 행사 대상에 OB 포함 여부를 지정하고 출석 창을 엽니다. QR과 입력 코드는 10분 동안 유효하며 재발급하면 이전 값은 즉시 무효가 됩니다. 코드가 유출되었다면 새 코드를 발급하고 현장에 표시합니다. 출석 창 종료 뒤 당시 대상 스냅샷의 미출석 기록이 남습니다. 운영진 정정에는 이유를 입력하며 수행자·시각·이전 상태·변경 상태가 감사 기록에 저장됩니다. 출석 시도 제한은 계정당 1분에 10회, IP당 1분에 100회입니다.

## 공지 투표

운영진은 공지에 참석·불참 또는 찬성·반대 투표를 하나 붙일 수 있습니다. 등록 뒤 질문·선택지·마감 시각은 변경할 수 없습니다. 승인된 단원은 마감 전까지 선택을 바꿀 수 있으며 계정별로 한 표만 집계됩니다. 단원에게는 집계와 본인 선택만, 운영진에게는 응답자 명단과 선택이 표시됩니다. 행사 출석 기록과는 별개입니다.

## 백업과 복구

DB 백업에는 회원, 인증 토큰 해시·세션, 행사·공지·출석, 출석 대상 스냅샷과 감사 기록이 포함되어야 합니다. 기존 메일 발송 대기열은 이전 버전 데이터 복구를 위해 스키마에 남아 있지만 새 계정 흐름에서 사용하지 않습니다. 백업 접근 권한을 제한하고 암호화된 저장소에 보관합니다. 복구 검증에서는 초대 토큰을 외부에 표시하지 않습니다.
