# 회원 포털 운영 절차

## 배포 전 결정

운영진은 최신 단원 명단의 관리 담당자와 대조 방법, 첫 운영진으로 초대할 사람, 개인별 계정 연결 링크를 전달할 비공개 채널을 정합니다. 명단과 연결 링크는 저장소에 넣지 않습니다. 배포 구성은 Vercel 웹, Render 유료 API, Supabase PostgreSQL입니다.

## 운영 전환 순서

1. 운영진이 명단을 확인하고 첫 운영진의 이름·로그인 이메일·단원 구분을 확정합니다.
2. Google Cloud에서 웹 애플리케이션용 OAuth 클라이언트 ID를 만들고 승인된 자바스크립트 출처에 실제 웹 HTTPS 출처를 등록합니다. 공개 클라이언트 ID는 Render Blueprint의 `GOOGLE_CLIENT_ID`와 Vercel 웹의 `NEXT_PUBLIC_GOOGLE_CLIENT_ID`에 같은 값으로 설정합니다. API·PostgreSQL 비밀값과 웹 HTTPS 주소를 준비하고 `.\deployment\check-launch-config.ps1 -PublicOrigin https://확정한-도메인`을 실행합니다. 배포 뒤 `-CheckLive`로 공개 화면과 `/api/v1/auth/csrf`를 확인합니다.
3. Supabase Data API를 사용하지 않으므로 배포 전에 프로젝트의 Data API를 끄고, 공개 스키마 테이블에 대한 외부 접근이 차단됐는지 확인합니다. 운영 DB 변경 전에 일관된 백업을 남기고, 격리 환경에서 복구와 Flyway 마이그레이션, 회원·행사·출석·감사 기록 조회를 확인합니다. 이미 적용된 마이그레이션 파일은 수정하지 않습니다.
4. 운영진 계정이 없다면 DB 접속 권한을 가진 배포 담당자가 API 프로젝트에서 `gradlew.bat bootstrapAdminInvite --args="<JDBC URL> <DB 사용자> <이메일> <이름> ACTIVE"`를 실행합니다. 초대된 최초 운영진의 이메일 소유를 구글이 보증하지 않거나 기존 승인 운영진에게 구글 계정을 연결해야 한다면 `gradlew.bat linkExistingAdminGoogle --args="<JDBC URL> <DB 사용자> <운영진 이메일>"`로 새 연결 토큰을 발급합니다. 이 명령은 이전 미사용 링크를 무효화하며, 이미 구글 계정이 연결된 운영진에게는 사용할 수 없습니다. DB 비밀번호는 콘솔 또는 일시적인 `CHOIR_BOOTSTRAP_DB_PASSWORD`로 공급합니다. 출력된 1회용 토큰을 실제 HTTPS 주소의 `/activate#token=<토큰>`에 붙여 운영진에게 비공개로 전달합니다. 공유 로그나 작업 티켓에 토큰을 남기지 않습니다.
5. 첫 운영진이 초대 이메일의 구글 계정으로 로그인합니다. 구글이 해당 이메일의 현재 소유를 보증하고 초기화 명령의 감사 기록이 있으면 첫 로그인에서 계정이 연결됩니다. 그렇지 않으면 1회용 연결 링크를 사용합니다. 이후 `/admin/members`에서 명단과 대조한 이메일을 자동 승인 명단에 추가하거나, 운영진으로 지정할 이메일을 운영진 사전 등록 목록에 추가합니다. 연결되지 않은 기존 계정에는 개인별 연결 링크를 발급합니다.
6. 처음 구글 로그인한 이메일이 자동 승인 명단에 있고 구글이 주소의 현재 소유를 보증하면 활동 단원 또는 OB로 바로 승인됩니다. 그 외에는 승인 대기 상태가 되고 운영진이 명단과 대조해 승인·반려합니다. 최초 운영진 초대의 위 조건을 제외한 기존 계정은 이메일만 같다는 이유로 연결되지 않으며 1회용 링크가 필요합니다. 링크는 한 번만 표시되고 한 번만 사용할 수 있습니다. 만료 또는 분실 시 운영진이 새 링크를 발급하며 이전 링크는 무효가 됩니다.
7. 실제 접속 경로에서 TLS, `Secure` 세션 쿠키, CSRF, 권한 경계, 프록시 전달 IP 위조 차단과 공용망 출석 시도 제한을 확인합니다. 소수 단원으로 공지·투표·행사·QR·코드 출석과 정정을 시범 수행합니다.
8. 직책은 `/admin/members`에서 사이트 관리자나 단장이 회원 행마다 부여합니다. 단장·부단장 지정과 사이트 관리자 지정은 사이트 관리자만 합니다. 직책은 승인된 활동 단원에게만 줄 수 있고, 접근을 해제하면 직책이 모두 지워집니다. 기존 `admin` 계정은 배포 뒤 그대로 사이트 관리자이며, 직책은 비어 있으므로 안내문에 맞춰 직접 부여합니다. 권한은 요청마다 다시 계산하므로 직책을 바꾼 뒤 다시 로그인할 필요가 없습니다.

Windows PowerShell에서 운영진 연결 링크를 재발급할 때는 `deployment/reissue-admin-google-link.ps1`을 사용합니다. 이 스크립트는 DB 비밀번호를 보안 입력받고 새 링크를 클립보드에 복사하며, 토큰을 터미널에 출력하지 않습니다.

각 단계의 담당자와 날짜, 결과를 운영 기록에 남깁니다. 구글 클라이언트 ID가 실제 배포 환경에 설정되기 전에는 구글 로그인 운영 검증이 완료되지 않습니다.

## 계정과 권한

구글 계정으로 로그인합니다. 구글의 고유 계정 식별값을 회원 계정에 연결하며, 최초 운영진 초대의 검증된 첫 로그인을 제외하고 이메일만으로 기존 계정을 자동 연결하지 않습니다. 자동 승인 명단은 활동 단원·OB 구분만 부여하고 운영진 권한은 부여하지 않습니다. 운영진 사전 등록 목록은 아직 계정이 없는 사람도 등록할 수 있으며, 구글이 이메일 소유를 확인한 첫 로그인에서 운영진 권한을 부여합니다. 두 명단에서 삭제해도 이미 부여된 접근·권한은 유지되므로 필요한 경우 별도로 접근 해제합니다. 수동 승인과 접근 해제 시 기존 세션은 무효화됩니다. 가입 신청자는 승인 대기 화면에서 자기 이름, 기수, 파트를 적어 저장합니다. 운영진은 단원 계정 화면의 승인 대기 행이나 가입 승인 화면에서 이 값을 자신이 아는 그 단원의 정보와 맞춰 본 뒤 승인하며, 승인하면 적은 값이 그대로 단원의 이름·기수·파트가 됩니다.

초대 토큰 원문은 DB에 저장하지 않고 SHA-256 해시만 저장합니다. 링크 원문은 발급 응답과 첫 운영진 초기화 명령에서 한 번만 확인할 수 있습니다. 링크를 전달받는 사람을 잘못 선택하면 계정에 접근할 수 있으므로, 운영진은 전달 전에 본인을 확인해야 합니다.

## 환경과 네트워크

로컬 Docker 검증에서도 `GOOGLE_CLIENT_ID`와 `NEXT_PUBLIC_GOOGLE_CLIENT_ID`에 같은 웹 클라이언트 ID를 설정합니다. 웹 값은 빌드 시 반영되므로 변경하면 다시 빌드해야 합니다.

`.env.example`은 변수 이름만 보여 줍니다. 실제 비밀번호는 저장소와 셸 기록에 남기지 않고 실행 환경의 비밀 저장소에서 공급합니다. 개발용 `compose.yaml`은 PostgreSQL만 루프백에 엽니다. `compose.portal.yaml`은 로컬 검증용 HTTP 프록시만 루프백에 노출합니다. 운영 환경에서는 HTTPS를 적용하고 쿠키의 `HttpOnly`, `Secure`, `SameSite=Lax`를 유지합니다. 배포 인그레스가 정해지면 신뢰 프록시 CIDR과 실제 접속 IP 전달·위조 차단을 다시 검증합니다.

## 행사와 출석 현장 대응

운영진은 행사 관리에서 월을 고르고 여러 날짜를 선택한 뒤 공통 종류·제목·시각으로 일정을 한 번에 등록합니다. 등록 후 각 행사의 시각과 내용을 개별 수정할 수 있습니다. 단원은 행사별 참석·불참 의사를 행사 시작 전까지 바꿀 수 있습니다. 운영진은 행사 관리에서 참석·불참·미응답 인원과 명단을 확인합니다. 이 사전 응답은 현장 QR 출석이나 출석 정정 기록을 변경하지 않습니다.

운영진은 행사 대상에 OB 포함 여부를 지정하고 출석 관리 화면에서 '출석 받기'를 눌러 출석 창을 엽니다. 출석 창은 연습 시작 30분 전부터 열 수 있고 연습이 끝나면 닫히며, 시작 15분 뒤부터 찍은 출석은 지각으로 기록됩니다. 연습이 늦게 끝나면 행사 종료 시각을 늦추면 창도 같이 늘어납니다. 입력 코드는 4자리 숫자이며 출석 관리 화면에서 언제든 다시 볼 수 있고, 재발급하면 이전 QR과 코드는 즉시 무효가 됩니다. 코드가 유출되었다면 새 코드를 발급하고 현장에 알립니다. 출석 창이 닫히거나 연습이 끝난 뒤 당시 대상 스냅샷의 미출석 기록이 남습니다. 운영진 정정에는 이유를 입력하며 수행자·시각·이전 상태·변경 상태가 감사 기록에 저장됩니다. 출석 시도 제한은 계정당 1분에 10회, IP당 1분에 100회입니다.

일정마다 종류(정기연습, 비정기연습, 파트연습, 중요 행사)가 있고, 파트연습은 파트를 하나 고릅니다. 정기연습과 비정기연습은 단장·부단장, 파트연습은 단장·부단장과 그 파트 수석, 중요 행사(연주회, 발표회, MT 등)는 운영진 누구나 등록·수정합니다. 단원의 '일정' 메뉴는 달마다 연습 횟수와 종류별 개수를 보여 주므로 종류를 맞게 골라 주세요. V8 배포 때 기존 전체연습과 제목에 '연습'이 든 일정은 제목에 '비정기'가 있으면 비정기연습, 없으면 정기연습으로 옮겨졌습니다. '최종 리허설'처럼 제목에 '연습'이 없는 일정과, 제목에 '파트'가 든 옛 파트연습은 파트를 알 수 없어 중요 행사로 남아 있습니다. 수정 화면에서 종류를 바꾸고, 파트연습이면 파트도 고릅니다. 출석 창을 닫거나 연습이 끝나면 출석하지 않은 대상 단원은 모두 미출석으로 남고, 출석 관리 화면에서는 이들을 '출석 대상 아님'으로 되돌릴 수 없습니다.

수석은 파트연습을 이렇게 진행합니다. 일정 관리에서 종류 '파트연습'과 자기 파트를 골라 등록합니다. 파트연습은 그 파트 단원과 운영진에게만 보이고, 참석 응답과 출석 대상은 그 파트 단원(OB 포함 일정이면 그 파트 OB도)뿐입니다. 응답 집계와 출석 관리(출석 창, 출석 명단, 정정)는 그 파트 수석, 단장·부단장·총무, 사이트 관리자가 합니다. 대상은 단원 정보의 파트로 정하므로, 파트가 비어 있거나 틀린 단원은 대상에서 빠집니다. 처음 파트연습 출석 창을 열기 전에 `/admin/members`에서 그 파트 단원들의 파트를 확인합니다.

연습장에 아직 승인되지 않은 가입 신청자가 오면 이렇게 처리합니다. 가입 신청자는 출석 목록에 나오지 않고 코드를 넣어도 출석할 수 없습니다. 가입 승인 권한이 있는 운영진이 `/admin/members`의 승인 대기 행이나 `/admin/applications`의 가입 승인 화면에서 명단과 대조해 승인합니다. 계정 행에서 승인하면, 직책 관리 권한이 있는 운영진은 활동 단원으로 승인한 사람에게 그 자리에서 바로 직책을 줄 수 있습니다. OB는 직책을 가질 수 없습니다. 승인하면 그 사람의 기존 로그인이 끝나므로 다시 로그인하게 한 뒤, 출석 창이 열려 있으면 현재 입력 코드를 다시 넣게 합니다. 출석 창이 이미 닫혔다면 출석 관리 화면에서 그 단원의 '출석 창 대기' 상태를 이유를 적어 출석으로 정정합니다.

## 공지 작성

운영진은 공지 관리에서 "새 공지 작성"으로 들어가 제목과 본문을 쓰고, 투표를 붙일지 고른 뒤 "초안으로 저장"하거나 "게시하기"를 누릅니다. 초안은 단원에게 보이지 않습니다. 공지 관리 목록에서 공지를 누르면 수정 화면이 열리고, 초안은 "게시하기"로 올리고 게시 중인 공지는 "초안으로 내리기"로 내립니다. 초안으로 내린 공지를 다시 게시하면 게시일이 새로 정해져 단원 목록 맨 위로 올라갑니다. 투표는 한 번 붙이면 질문, 선택지, 마감 시각을 바꿀 수 없습니다. 쓰다 만 새 공지는 같은 탭에 임시 저장되어 로그인이 끊겼다 돌아와도 되살아납니다.

## 공지 투표

운영진은 공지에 참석·불참 또는 찬성·반대 투표를 하나 붙일 수 있습니다. 등록 뒤 질문·선택지·마감 시각은 변경할 수 없습니다. 승인된 단원은 마감 전까지 선택을 바꿀 수 있으며 계정별로 한 표만 집계됩니다. 단원에게는 집계와 본인 선택만, 운영진에게는 응답자 명단과 선택이 표시됩니다. 행사 출석 기록과는 별개입니다.

단원 공지 목록에는 투표가 있는 공지만 상태 배지를 표시합니다. 미참여는 회색, 응답한 투표는 본인 선택만 초록색, 마감은 회색과 기존 본인 선택으로 표시합니다. 선택지를 누르는 것만으로 상태를 바꾸지 않으며 저장 성공 응답 이후 목록을 갱신합니다. 목록을 열어 둔 동안 마감 시각이 지나면 마감 배지로 전환하고, 실제 투표 허용 여부는 서버에서 판정합니다. 일반 공지에는 배지를 붙이지 않습니다.

목록 API는 현재 페이지의 투표 요약과 로그인한 단원의 선택만 한 번의 추가 조회로 반환합니다. 응답자 명단과 이메일은 포함하지 않습니다. DB 마이그레이션은 필요하지 않으며, 웹 배포 전에 API의 목록 응답에 `poll` 요약 필드가 포함되는지 확인합니다.

## 백업과 복구

DB 백업에는 회원, 인증 토큰 해시·세션, 행사·공지·사전 참석 응답·현장 출석, 출석 대상 스냅샷과 감사 기록이 포함되어야 합니다. 기존 메일 발송 대기열은 이전 버전 데이터 복구를 위해 스키마에 남아 있지만 새 계정 흐름에서 사용하지 않습니다. 백업 접근 권한을 제한하고 암호화된 저장소에 보관합니다. 복구 검증에서는 초대 토큰을 외부에 표시하지 않습니다.
