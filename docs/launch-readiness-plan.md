# 운영 전환 준비 계획

계정·메일 항목은 당시 설계의 기록입니다. 현재 운영 기준은 [운영진 계정 발급 스펙](operator-accounts-spec.md)과 [운영 절차](operations.md)를 따릅니다.

작성일: 2026-09-29
기준: [운영 전환 준비 스펙](launch-readiness-spec.md)

## 1. 현재 배포 경계 확인

- 로컬 Compose와 프록시, API 환경 설정, 기존 운영 절차를 점검한다.
- 실제 배포 장소가 정해지기 전까지 로컬 HTTP 구성을 운영 배포 설정으로 사용하지 않는다.

## 2. 설정 사전 점검

- 환경 변수의 존재와 공개 HTTPS 주소·이메일 확인 링크의 일치를 검사한다.
- 오류 메시지에는 변수명과 점검 항목만 표시하고 비밀값은 출력하지 않는다.
- 정상·누락·잘못된 주소 사례로 점검 도구를 실행한다.

## 3. 운영 절차와 검증 기록

- 운영진 승인, SMTP 실송수신, 최초 운영진, 명단 대조, 백업 복구, 시범 사용 순서를 문서화한다.
- 배포 토폴로지가 정해지면 프록시 신뢰 범위와 TLS 구성, 현장 접속 IP 제한을 그 환경에서 확인한다.
- 미정인 외부 정보는 미완료로 남긴다.

## 4. 결과

- 설정 점검과 문서 작성 결과를 확인해 별도 기능 커밋으로 남긴다.
- 실제 서버 설정과 시범 운영은 운영진과 배포 정보가 확정된 뒤 실행한다.

## 실행 결과

- 운영 설정 사전 점검 스크립트를 추가했다. 필수 환경 변수와 SMTP 포트, 공개 HTTPS 주소, 이메일 확인 주소의 일치를 검사하고 선택적으로 실제 HTTPS 화면과 API 응답을 확인한다.
- 가짜 값으로 정상 설정은 통과, 변수 누락·HTTP 주소·예시 도메인·다른 확인 주소·잘못된 SMTP 포트는 실패하는 것을 확인했다. Windows PowerShell에서 한국어 결과가 깨지지 않도록 UTF-8 인코딩도 확인했다.
- 운영 절차에 담당자 확정, 백업 복구, 실제 메일, 프록시 경계와 시범 사용 순서를 적었다.
- 배포 장소와 실제 도메인·SMTP·최초 운영진·명단 대조 방식이 정해지지 않아 실제 HTTPS 및 운영 흐름은 실행하지 않았다.
