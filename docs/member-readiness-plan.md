# 단원 사용 준비 구현 계획

작성일: 2026-09-28
기준: [단원 사용 준비 스펙](member-readiness-spec.md)

## 1. 기존 기능과 검증 기준 확인

- 가입, 승인, 회원 조회, 운영진 변경, 출석의 기존 화면과 API를 대조한다.
- 웹 단위 테스트·린트·빌드와 API 테스트를 먼저 실행해 변경 전 상태를 기록한다.
- 변경된 디자인과 현재 브라우저 테스트의 선택자·문구가 일치하는지 확인한다.

## 2. 가입·운영진 화면 정리

- 가입 신청·상태 화면을 기존 로그인 화면과 같은 입력 규칙으로 정리한다.
- 운영진 공통 내비게이션을 추가하고 신청 목록, 공지 편집, 행사 편집, 출석 관리의 색·간격·입력·상태 표시를 회원 화면과 맞춘다.
- 기존 승인·저장·출석 API 계약을 유지하고 요청 중 중복 제출 및 실패 복구를 확인한다.
- 390px 화면에서 목록과 입력 폼이 정상적으로 이어지는지 확인한다.

## 3. 격리 브라우저 검증 확대

- 현재 사용 중인 로컬 미리보기 포트와 충돌하지 않도록 E2E의 웹·DB·메일 포트와 전용 내부 네트워크를 분리한다.
- 신청·승인·일정·출석·정정, 공개 자료 경계, 운영진 화면 탐색, 모바일 가로 넘침과 브라우저 오류를 검증한다.
- 테스트 실행기가 자신이 만든 자원만 정리하는 기존 안전 조건을 유지한다.

## 4. 최종 검증과 결과 정리

- API 전체 테스트, 웹 단위 테스트, 린트, 빌드, 브라우저 통합 테스트를 실행한다.
- 실패 원인만 수정한 뒤 해당 검증을 다시 실행한다.
- 변경 파일, 실제 통과 결과, 남은 운영 준비 항목을 구분해 보고한다. 실제 운영 환경은 이 작업에서 배포하지 않는다.

## 실행 결과

- 가입 신청·상태 화면과 운영진 공통 이동 경로, 신청·공지·행사·출석 관리 화면을 정리했다. 신청 목록 조회 실패 시 재시도할 수 있도록 수정했다.
- 격리 브라우저 테스트는 사용 가능한 포트와 별도 내부 네트워크를 사용한다. MySQL의 준비 확인은 실제 TCP 연결과 쿼리 성공을 기준으로 바꿨다.
- API 강제 재실행: 12개 테스트 모음, 51개 테스트 통과. 웹: 14개 테스트 파일, 48개 테스트 통과. 린트·프로덕션 빌드 통과. 브라우저 통합 테스트 2개 통과.
- 통합 테스트에서 가입 → 이메일 확인 → 운영진 승인 → 로그인 → 일정 → 코드 출석 → 정정 반영을 확인했다. QR 토큰 처리와 재발급 무효화는 웹·API 테스트로 확인했다. 운영진 화면 네 곳과 회원 일정 화면의 390px 가로 넘침을 확인했다.
- 실제 메일 발송, 서비스 주소·HTTPS, 첫 운영진과 명단 대조 절차, 실제 단원 시범 사용은 운영 준비가 필요하다. 이 작업에서 운영 배포하지 않았다.
