# 구글 로그인 전환 구현 계획

기준: [구글 로그인과 단원 승인 스펙](google-login-spec.md)

1. PostgreSQL에 구글 고유 식별값과 화이트리스트를 추가하는 새 Flyway 마이그레이션을 작성합니다. 적용된 마이그레이션은 수정하지 않습니다.
2. 구글 ID 토큰 검증, 최초 로그인·재로그인·승인 대기·화이트리스트 자동 승인·기존 계정 연결을 API에 구현합니다. 기존 세션·권한·CSRF 규칙을 유지하고 비밀번호 로그인 경로를 닫습니다.
3. 운영진의 화이트리스트 등록·조회·삭제와 기존 승인·반려·접근 해제 화면을 연결합니다. 자동 승인은 화이트리스트의 단원 구분을 사용하며 운영진 권한을 부여하지 않습니다.
4. 로그인과 계정 연결 화면을 구글 로그인으로 전환하고 비밀번호 설정 화면을 제거합니다. 승인 대기·반려·접근 해제 상태를 명확히 표시합니다.
5. 운영 절차와 Render·Vercel 설정에 Google Cloud 웹 클라이언트 ID와 승인된 사이트 출처를 반영합니다. 기존 운영진 계정은 DB 관리자용 1회용 연결 명령으로 이전합니다. 실제 ID가 없어도 API가 기동하되 구글 인증 요청은 설정 오류로 거부합니다.
6. 서명·발급자·수신 대상 검증, 화이트리스트·수동 승인, 기존 계정 충돌, 운영진 권한, 세션 무효화, 웹 화면을 테스트합니다. 실제 구글 계정 검증과 첫 운영진 초기화는 운영 정보가 확보된 뒤 수행합니다.

데이터, API, 웹, 운영 설정은 각각 검토 가능한 기능 커밋으로 남깁니다. 운영 자격 증명은 저장소에 넣지 않습니다.
